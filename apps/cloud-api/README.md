# Rox Cloud API (BYOK)

Публичный HTTP-интерфейс Rox Cloud. Арендатор приносит свой ключ провайдера
(Daytona), Rox хранит его в зашифрованном виде и запускает машины на счёте
самого арендатора. Поэтому **счёт за железо платит арендатор напрямую
Daytona**, а кошелёк Rox хранит только вознаграждение платформы.

## Запуск

```bash
cd apps/cloud-api
bun run start            # порт 8787
bun test
bunx tsc --noEmit
```

## Переменные окружения

| Переменная | Смысл |
| --- | --- |
| `PORT` | Порт API, по умолчанию `8787`. |
| `ROX_BOOTSTRAP_KEY` | Полный ключ вида `rox_sk_live_…`. Если в хранилище ещё нет ключей, при старте создаётся один арендатор и один ключ с этим секретом: в хранилище остаётся только SHA-256, сам секрет никуда не пишется. |
| `ROX_BOOTSTRAP_TENANT` | Имя этого первого арендатора, по умолчанию «Моя команда». |
| `ROX_MASTER_KEY` | Ключ шифрования хранилища ключей провайдеров: **base64 ровно от 32 байт**. Пример: `openssl rand -base64 32`. |
| `ROX_PLATFORM_RATE_CENTS_PER_HOUR` | Ставка Rox в **центах за час** работы одной машины, целое число больше нуля. Это ставка платформы, а не цена провайдера. |
| `ROX_BOOTSTRAP_BALANCE_CENTS` | Необязательный стартовый баланс кошелька первого арендатора в центах; начисляется один раз при старте. |
| `ROX_ADMIN_KEY` | Ключ дежурного для панели `/admin/`. Без него панель отвечает 404 и ничего не придумывает вместо пароля. Сравнение идёт в постоянном времени, сам ключ никуда не пишется и не логируется. |
| `ROX_CORS_ORIGIN` | Необязательный список источников через запятую (`https://panel.example`). Пусто — браузеру разрешён только тот же источник, на котором открыта страница. Чужой источник не отражается. |

`ROX_MASTER_KEY` и `ROX_PLATFORM_RATE_CENTS_PER_HOUR` включают настоящее
исполнение: ключи провайдеров, резерв вознаграждения, рубильник и журнал
действий. Без них сервис поднимается с честной заглушкой: провайдер есть, но
он заявляет ноль возможностей, и ни одна машина не запускается.

```bash
ROX_BOOTSTRAP_KEY=rox_sk_live_… \
ROX_BOOTSTRAP_TENANT='Моя команда' \
ROX_BOOTSTRAP_BALANCE_CENTS=1000 \
ROX_MASTER_KEY="$(openssl rand -base64 32)" \
ROX_PLATFORM_RATE_CENTS_PER_HOUR=25 \
ROX_ADMIN_KEY="$(openssl rand -hex 24)" \
PORT=8787 bun run start
```

## Страницы на том же адресе

Один процесс отдаёт и API, и обе страницы, поэтому браузеру не нужен
межсайтовый запрос:

| Адрес | Что отдаётся |
| --- | --- |
| `GET /`, `/docs.html`, `/pricing.html`, `/status.html`, `/styles.css` | Сайт Rox Cloud из соседней папки `apps/cloud-site`. |
| `GET /console/`, `/console/app.js`, `/console/styles.css` | Консоль арендатора из соседней папки `apps/cloud-console` (чистый HTML, CSS, JS). |
| `GET /admin/` | Панель дежурного: один файл `public/admin.html` без внешних ресурсов. |

Проверка одной командой: `scripts/cloud-smoke.sh` поднимает сервис на свободном
порту и проверяет `/health`, `/`, `/docs.html`, `/console/`, `/admin/`, баланс
первого арендатора и список клиентов в панели.

Страницы отдаются по фиксированному списку путей: запрос не описывает файл, а
выбирает один из них, поэтому `..` в адресе не открывает дерево исходников.

## Панель дежурного

Панель открывается по `/admin/` и подключается адресом API и ключом дежурного;
ключ живёт только в этой вкладке (`sessionStorage`). Разделы: «Обзор»,
«Клиенты», «Ресурсы», «Ключи поставщиков», «Рубильник», «Журнал».

| Запрос | Что делает |
| --- | --- |
| `GET /admin/overview` | Счётчики: арендаторы, работающие машины, ключи, сумма на счетах, открытые рубильники. |
| `GET /admin/tenants` | Арендаторы с балансом, резервом, расходом за месяц, числом машин и ключей. |
| `GET /admin/resources?tenant=&state=&provider=` | Машины всех арендаторов с фильтрами. |
| `POST /admin/resources/{id}/stop` (`{reason}`) | Остановка чужой машины: три шага обычной остановки плюс запись в журнал от `staff`. Без причины — 400. |
| `GET /admin/credentials` | Только метаданные ключей поставщиков: ни секрета, ни шифротекста, ни вектора, ни тега. |
| `GET` и `POST /admin/killswitch` | Список запросов блокировки и новый запрос `{scope:{provider?,region?,product?},enabled,reason}`. |
| `POST /admin/killswitch/{id}/approve` | Подтверждение ожидающего запроса вторым сотрудником. |
| `POST /admin/killswitch/{id}/disable` (`{reason}`) | Снятие блокировки с причиной. |
| `GET /admin/audit?limit=` | Журнал действий, новые сверху. |
| `GET /admin/health` | `{ok:true, runtime}`: отвечает ли панель и настроено ли исполнение. |

Все ответы об ошибке используют тот же конверт, что и публичный API:
`{error:{type, code, message, request_id}}`, и каждая страница показывает
сообщение сервера, код и идентификатор запроса.

Рубильник двухместный: запрос создаётся от `staff:requester`, подтверждается от
`staff`, и правило «подтверждает другой» не даёт включить блокировку одним
действием. Один общий ключ дежурного не различает людей, поэтому журнал хранит
оба шага отдельными записями с причиной.

`OPTIONS` отвечает 204 на любом пути; заголовки CORS добавляются только для
источника из `ROX_CORS_ORIGIN`.

## Что происходит при запуске машины

1. Арендатор добавляет свой ключ Daytona: `POST /v1/provider-credentials`
   (`{provider,label,secret,spendCapCents,regions?}`). В ответе только
   метаданные: `id`, `last4`, `fingerprint`, `status`, потолок расхода.
   Ни зашифрованный текст, ни сам ключ в ответах не появляются.
2. `POST /v1/sandboxes` с заголовком `Idempotency-Key` проходит три проверки:
   рубильник (`kill_switch_active` → 409), потолки счёта
   (`concurrency_exceeded`/`monthly_cap_exceeded` → 409, `sandbox_too_large` →
   400) и кошелёк (`entitlement_required`/`insufficient_balance`/`budget_exceeded`
   → 402). Каждый отказ возвращает свой код в `error.code`, а не общий
   «платёж нужен». При удаче вознаграждение за весь срок резервируется на
   кошельке.
3. Провайдер получает расшифрованный ключ арендатора и создаёт машину у Daytona;
   железо оплачивает арендатор по своему счёту.
4. `POST /v1/sandboxes/{id}/stop` закрывает резерв и списывает фактическое
   время работы (минимум 1 цент), `DELETE` возвращает неиспользованный остаток.

## Маршруты

- `GET /health` — жив ли процесс.
- `GET /v1/catalog` — продукты и провайдеры, которые действительно умеют работать.
- `GET /v1/account`, `POST /v1/account/topup` — кошелёк платформы.
- `GET|POST /v1/keys`, `DELETE /v1/keys/{id}` — ключи API арендатора.
- `GET|POST /v1/provider-credentials`, `POST /v1/provider-credentials/{id}/promote`,
  `DELETE /v1/provider-credentials/{id}` — ключи провайдеров (нужно право `keys:write`).
- `POST|GET /v1/sandboxes`, `GET|DELETE /v1/sandboxes/{id}`,
  `POST /v1/sandboxes/{id}/stop`, `POST /v1/sandboxes/{id}/exec`,
  `GET|PUT /v1/sandboxes/{id}/files`.
- `GET /v1/usage` — расход по арендатору.

## Границы этого среза

- **Всё в памяти процесса.** Арендаторы, ключи, кошельки и машины исчезают при
  перезапуске; это пилот, а не биллинговая база. Ключи провайдеров лежат в
  памяти зашифрованными и тоже не переживают перезапуск.
- Из провайдеров подключён только **Daytona**. Ключи Modal и E2B можно
  положить в хранилище, но адаптера у них пока нет, и в каталоге они не
  рекламируются.
- Расход на железо идёт по счёту арендатора у провайдера; Rox выставляет только
  своё вознаграждение по ставке `ROX_PLATFORM_RATE_CENTS_PER_HOUR`.
- Секреты не пишутся в журнал и не возвращаются ни в одном ответе; в журнале
  действий у записи арендатора только `actorId = tenant:<id>`, тип `sandbox`,
  идентификатор машины и причина `customer request`.
- Панель дежурного — один общий ключ и те же хранилища в памяти: несколько
  дежурных не различимы по имени, а журнал и рубильник исчезают при
  перезапуске вместе с остальным состоянием. Список ключей поставщиков панель
  показывает без секрета: только `last4`, отпечаток, состояние и потолок.
