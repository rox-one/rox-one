# Rox Cloud API

Публичный HTTP-интерфейс Rox Cloud: сайт с продуктами и ценами, кабинет с
конфигуратором и терминалом, панель дежурного. Один процесс отдаёт страницы и
API на одном адресе.

Две схемы оплаты одной машины:

- **managed** — своего ключа провайдера у клиента нет, машина идёт на
  платформенном ключе Rox, кошелёк платит полную цену часа. Так работают гости
  и новые клиенты.
- **byok** — у клиента есть свой ключ, машина идёт на нём, кошелёк платит
  только сервисный сбор. Железо клиент оплачивает провайдеру напрямую.

Цена считается по разрешённому снимку, а не по полям вызывающего. Создание
принимает `product` (код из таблицы) или `snapshot`; сервер берёт cpu / память /
диск / GPU из каталога или живого списка образов. Поля `cpu`, `memoryGb`,
`diskGb`, `gpu` в теле — только проверка: расхождение даёт `invalid_request`.
Снимок `daytona-gpu` всегда стоит 786 ¢/ч, даже если в теле просят одно ядро;
неизвестный снимок — отказ до резерва.

Linux-продукты запускаются с реальных снимков этого аккаунта:
`daytonaio/sandbox:0.11.0`, `rox-cloud-medium-2x4`, `rox-cloud-large-4x8`.
Каталог отдаёт у продукта `available` и `note`: Windows-класс в этом аккаунте
недоступен, GPU-кредитов нет — такие строки видны с ценой и объяснением, а
запуск по `product` отвечает `capability_unavailable` до резерва. Свой снимок
(`snapshot` в теле) по-прежнему разрешён: если провайдер его не пускает, ответ
честный.

Цена считается по составу машины в целых центах за час
(`packages/cloud-pricing`): `10 + 6×cpu + 3×memoryGb + 0,2×diskGb + gpu`,
с округлением вверх. Сервисный сбор при своём ключе:
`max(5, round(цена × 0,15))`. Каждая машина хранит свою ставку, режим и
площадку; счётчик, резерв, расчёт при остановке и счёт читают их.

## Запуск

```bash
cd apps/cloud-api
bun run start            # порт 8787
bun test
bunx tsc --noEmit
```

## Переменные окружения

| Переменная | Смысл |
| --- | --- |
| `PORT` | Порт API, по умолчанию `8787`. |
| `ROX_BOOTSTRAP_KEY` | Полный ключ вида `rox_sk_live_…`. Если в хранилище ещё нет ключей, при старте создаётся один арендатор и один ключ с этим секретом: в хранилище остаётся только SHA-256, сам секрет никуда не пишется. |
| `ROX_BOOTSTRAP_TENANT` | Имя этого первого арендатора, по умолчанию «Моя команда». |
| `ROX_MASTER_KEY` | Ключ шифрования хранилища ключей провайдеров: **base64 ровно от 32 байт**. Пример: `openssl rand -base64 32`. |
| `ROX_PLATFORM_RATE_CENTS_PER_HOUR` | Запасная ставка Rox в **центах за час** работы одной машины, целое число больше нуля. Используется, только когда машина продана без прайс-листа (старое состояние) — обычная цена приходит из `packages/cloud-pricing`. |
| `ROX_PLATFORM_DAYTONA_KEY` | Ключ Daytona, которым Rox платит за managed-машины. Наружу не уходит: только последние 4 символа видны панели. Без него managed-машины отвечают `capability_unavailable`, а каталог не рекламирует managed. |
| `DAYTONA_API_KEY` | Запасное имя того же платформенного ключа, если `ROX_PLATFORM_DAYTONA_KEY` не задан. |
| `ROX_PLATFORM_DAYTONA_URL` | Необязательный адрес API Daytona для платформенного ключа; по умолчанию публичный `https://app.daytona.io/api`. |
| `ROX_GUEST_ENABLED` | `1` включает публичный гостевой вход `POST /v1/guest`. Пусто или `0` — маршрут отвечает 403 `guest_disabled`. |
| `ROX_GUEST_TRIAL_CENTS` | Пробный баланс гостя в центах, по умолчанию `2000` (20,00 $). Он же становится месячным потолком гостя. |
| `ROX_BOOTSTRAP_BALANCE_CENTS` | Необязательный стартовый баланс кошелька первого арендатора в центах; начисляется один раз при старте. |
| `ROX_ADMIN_KEY` | Ключ дежурного для `/v1/admin/*`. Без него панель отвечает 404 и ничего не придумывает вместо пароля. Сравнение идёт в постоянном времени, сам ключ никуда не пишется и не логируется. |
| `ROX_CORS_ORIGIN` | Необязательный список источников через запятую (`https://panel.example`). Пусто — браузеру разрешён только тот же источник, на котором открыта страница. Чужой источник не отражается. |
| `ROX_MODAL_BRIDGE_URL` | Адрес мостика `apps/modal-bridge` внутри Modal. Без него провайдер Modal не рекламируется и его ключи не используются. |
| `ROX_DEMO_TENANT_ID` | Арендатор, на чьём ключе работает публичная проба `/v1/demo`. Без него страница пробы открывается, а запуск отвечает `demo_unavailable`. |
| `ROX_STATE_FILE` | Путь к файлу состояния. Если задан, клиенты, ключи, кошелёк, журнал, ставки машин и ключи поставщиков переживают перезапуск, а при остановке сервиса запущенные машины сначала останавливаются и закрывают счёт. Без переменной всё живёт только в памяти. |
| `ROX_E2B_TEMPLATE` | Имя шаблона E2B, из которого запускаются машины. Без него провайдер E2B не рекламируется и его ключи не используются. |
| `ROX_E2B_SANDBOX_HOST` | Необязательный адрес прокси песочниц E2B; по умолчанию публичный `https://sandbox.e2b.app`. |

`ROX_MASTER_KEY` и `ROX_PLATFORM_RATE_CENTS_PER_HOUR` включают настоящее
исполнение: ключи провайдеров, резерв вознаграждения, рубильник и журнал
действий. Без них сервис поднимается с честной заглушкой: провайдер есть, но
он заявляет ноль возможностей, и ни одна машина не запускается.

```bash
ROX_BOOTSTRAP_KEY=rox_sk_live_… \
ROX_BOOTSTRAP_TENANT='Моя команда' \
ROX_BOOTSTRAP_BALANCE_CENTS=1000 \
ROX_MASTER_KEY="$(openssl rand -base64 32)" \
ROX_PLATFORM_DAYTONA_KEY=… \
ROX_GUEST_ENABLED=1 \
ROX_GUEST_TRIAL_CENTS=2000 \
ROX_ADMIN_KEY="$(openssl rand -hex 24)" \
PORT=8787 bun run start
```

## Страницы на том же адресе

Страницы собираются в `apps/cloud-web` (SolidJS) и кладутся в
`apps/cloud-api/public/app`; сервер отдаёт их на `/`, `/console/*` и `/admin/*`,
а API остаётся первым. Перед первым запуском соберите интерфейс:
`bun run --cwd apps/cloud-web build`. Старые `apps/cloud-site`,
`apps/cloud-console` и `public/admin.html` удалены: их заменило одно приложение.

| Адрес | Что отдаётся |
| --- | --- |
| `GET /`, `/pricing`, `/docs`, `/status` | Сайт: продукты Rox Cloud, их состав и цена за час. «Купить» ведёт в кабинет без регистрации. |
| `GET /console`, `/console/machines…` | Кабинет: конфигуратор, машины, терминал, счёт, ключи, поставщики, журнал. |
| `GET /admin`, `/admin/clients…` | Панель дежурного: клиенты, балансы, ключи, машины, журнал действий и запросов, рубильник. |

Каждый ответ API — JSON с конвертом
`{error:{type, code, message, request_id}}` при ошибке и заголовком
`x-request-id` на любом ответе.

## Гостевой вход

`POST /v1/guest` — публичный, без ключа. Включается `ROX_GUEST_ENABLED=1` и
работает не чаще 5 раз в час с одного адреса (`X-Forwarded-For` или
`X-Real-IP`). Создаёт арендатора `guest-…`, один ключ и пробный баланс:
2000 ¢ по умолчанию. Ограничения гостя: 1 машина одновременно, не больше 16
ядер, месячный потолок равен пробному балансу, срок жизни машины не больше
24 часов. Ответ:

```json
{ "object": "guest", "tenant": { "id": "guest-…", "name": "Гость" },
  "api_key": "rox_sk_live_…", "balance_cents": 2000 }
```

Ключ больше нигде не появится: он живёт только в `sessionStorage` вкладки.
Гость своего ключа провайдера не имеет, поэтому машины запускаются managed —
на платформенном ключе Rox.

## Кабинет и панель

Кабинет работает своим ключом арендатора. Панель подключается `/v1/admin` и
ключом дежурного; ключ живёт только в этой вкладке (`sessionStorage`).

| Запрос | Что делает |
| --- | --- |
| `GET /v1/catalog` | Продукты с полной ценой и сервисным сбором, провайдеры, `managed_providers`. |
| `GET /v1/providers/{id}/images` | Живые образы: для Daytona — активные снимки (`GET /snapshots`) своим или платформенным ключом. |
| `POST /v1/sandboxes` | Запуск: принимает `product` или `snapshot` (цена по снимку) и `region`, считает цену и режим, резервирует ставку. |
| `GET /v1/sandboxes/{id}` | Состав (`spec`), площадка (`region`), режим и цена (`billing`). |
| `POST /v1/sandboxes/{id}/exec` | Команда в машине: `{command, cwd?, timeout_sec?}` → `{stdout, stderr, exit_code}`. |
| `GET /v1/usage`, `GET /v1/usage?format=csv` | Счёт: снимок, режим, ставка, розница, сбор, начало, остановка; CSV для скачивания. |
| `GET /v1/audit?limit=&action=&since=` | Журнал действий своего клиента, без чужих и без действий дежурного. |
| `GET /v1/account` | Кошелёк платформы. Клиентского пополнения нет: деньги добавляет только дежурный через `POST /v1/admin/tenants/{id}/credit`, а кнопка «Пополнить» в кабинете открывает обращение. |
| `GET|POST /v1/keys`, `DELETE /v1/keys/{id}` | Ключи API арендатора. |
| `GET|POST /v1/provider-credentials`, `POST /v1/provider-credentials/{id}/promote`, `DELETE /v1/provider-credentials/{id}` | Ключи провайдеров (право `keys:write`). |
| `POST|GET /v1/sandboxes`, `GET|DELETE /v1/sandboxes/{id}`, `POST /v1/sandboxes/{id}/stop`, `GET|PUT /v1/sandboxes/{id}/files` | Машины и файлы. |
| `GET /v1/usage` | Расход по арендатору. |
| `GET /v1/status`, `GET|POST /v1/tickets…` | Публичное состояние и обращения клиента. |
| `GET /v1/admin/overview` | Счётчики: арендаторы (и гости), работающие машины, ключи, деньги на счетах, открытые рубильники, платформенные ключи (только `last4`). |
| `GET /v1/admin/tenants`, `GET /v1/admin/tenants/{id}` | Клиенты: баланс, резерв, расход, лимиты, машины, ключи, деньги и действия. |
| `POST /v1/admin/tenants/{id}/credit` (`{amountCents,reason}`) | Пополнение кошелька. |
| `PATCH /v1/admin/tenants/{id}` (`{monthlyCapCents?,paid?,reason}`) | Потолок и платный доступ. |
| `POST /v1/admin/tenants/{id}/rotate-key` (`{reason}`) | Новый ключ: все старые отозваны и получают 401, секрет виден один раз. |
| `GET /v1/admin/keys?tenant=` | Ключи клиентов: имя владельца, `prefix`, `last4`, даты, `revoked_at`, баланс и резерв. |
| `GET /v1/admin/resources?tenant=&state=&provider=`, `POST /v1/admin/resources/{id}/stop` | Все машины и остановка чужой машины с причиной. |
| `GET /v1/admin/requests?tenant=&limit=` | Последние запросы API: время, метод, путь, код, длительность, клиент, `key_last4`, адрес. Тела и `Authorization` не хранятся; кольцо на 500 строк. |
| `GET /v1/admin/audit?tenant=&action=&since=&limit=` | Журнал действий, новые сверху, с фильтрами. |
| `GET` и `POST /v1/admin/killswitch`, `POST /v1/admin/killswitch/{id}/approve`, `POST /v1/admin/killswitch/{id}/disable` | Рубильник: запрос, подтверждение вторым сотрудником, снятие. |
| `GET /v1/admin/credentials` | Только метаданные ключей поставщиков: ни секрета, ни шифротекста, ни вектора, ни тега. |
| `GET /v1/admin/tickets…`, `GET|POST /v1/admin/incidents…`, `GET /v1/admin/abuse…` | Обращения, происшествия, злоупотребления. |
| `GET /v1/admin/health` | `{ok:true, runtime}`: отвечает ли панель и настроено ли исполнение. |

Рубильник двухместный: запрос создаётся от `staff:requester`, подтверждается от
`staff`, и правило «подтверждает другой» не даёт включить блокировку одним
действием. Один общий ключ дежурного не различает людей, поэтому журнал хранит
оба шага отдельными записями с причиной.

`OPTIONS` отвечает 204 на любом пути; заголовки CORS добавляются только для
источника из `ROX_CORS_ORIGIN`.

## Что происходит при запуске машины

1. Арендатор либо добавляет свой ключ Daytona (`POST /v1/provider-credentials`,
   `{provider,label,secret,spendCapCents,regions?}`), либо полагается на
   платформенный. В ответе на добавление только метаданные: `id`, `last4`,
   `fingerprint`, `status`, потолок расхода.
2. `POST /v1/sandboxes` с заголовком `Idempotency-Key` находит провайдера и
   режим: свой ключ → `byok`, иначе платформенный → `managed`. Без обоих —
   `capability_unavailable`. Затем три проверки: рубильник
   (`kill_switch_active` → 409), потолки счёта — общие и клиентские, у гостя
   свои (`concurrency_exceeded`/`monthly_cap_exceeded` → 409,
   `sandbox_too_large` → 400), кошелёк
   (`entitlement_required`/`insufficient_balance`/`budget_exceeded` → 402).
3. Цена считается по составу; ставка режима резервируется на весь срок и
   записывается в машину вместе с `region`. Счётчик, остановка и счёт читают
   именно её.
4. Провайдер создаёт машину: Daytona получает снимок и, если площадка задана,
   `target`.
5. `POST /v1/sandboxes/{id}/stop` закрывает резерв и списывает фактическое
   время по ставке машины (минимум 1 цент), `DELETE` возвращает
   неиспользованный остаток.

## Границы этого среза

- **Всё в памяти процесса.** Арендаторы, ключи, кошельки и машины исчезают при
  перезапуске без `ROX_STATE_FILE`; это пилот, а не биллинговая база. Ключи
  провайдеров лежат зашифрованными.
- Из провайдеров подключён только **Daytona**. Ключи Modal и E2B можно
  положить в хранилище, но адаптера у них пока нет, и в каталоге они не
  рекламируются.
- Платформенный ключ Daytona не покидает `platform.ts`: он уходит только в
  адаптер, а наружу — ни в лог, ни в ошибку, ни в JSON, ни в HTML.
  Панель видит последние 4 символа.
- Старое состояние без ставки и режима читается как раньше: ставка
  `ROX_PLATFORM_RATE_CENTS_PER_HOUR`, режим `byok`.
- Гостевой ключ — платформенный; лимиты и потолок обязательны, иначе гости
  жгут счёт. Свой снимок гость создать не может.
- Панель дежурного — один общий ключ и те же хранилища в памяти: несколько
  дежурных не различимы по имени, а журнал и рубильник исчезают при
  перезапуске вместе с остальным состоянием. Список ключей поставщиков панель
  показывает без секрета: только `last4`, отпечаток, состояние и потолок.
