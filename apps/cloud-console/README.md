# Rox Cloud — консоль

Одностраничная консоль для Rox Cloud: подключение по ключу, песочницы, расход,
ключи, ключи поставщиков и журнал действий этой вкладки. Чистые HTML, CSS и
JavaScript: без сборки, без зависимостей, без внешних шрифтов и картинок.

## Как запустить

```sh
python3 -m http.server 8080 -d apps/cloud-console
```

Откройте `http://localhost:8080` и введите адрес API и ключ.

По умолчанию консоль обращается к `http://localhost:8787` — это локальный
`apps/cloud-api` (контракт лежит в `apps/cloud-api/openapi.yaml`). Адрес можно
поменять на экране подключения; он сохраняется в `localStorage`.

Позже консоль может отдавать сам API с того же адреса. Тогда адрес API — адрес
страницы, и отдельный веб-сервер не нужен.

## Какой API ожидается

Ключ передаётся заголовком `Authorization: Bearer rox_sk_live_...`.

| Что делает консоль | Запрос |
| --- | --- |
| Проверка ключа при подключении | `GET /v1/catalog` |
| Обзор | `GET /v1/usage`, `GET /v1/sandboxes`, `GET /v1/keys` |
| Список песочниц и автообновление раз в 5 секунд | `GET /v1/sandboxes?limit=50` |
| Создание песочницы | `POST /v1/sandboxes` с заголовком `Idempotency-Key` |
| Команда в песочнице | `POST /v1/sandboxes/{id}/exec` |
| Остановка | `POST /v1/sandboxes/{id}/stop` |
| Удаление | `DELETE /v1/sandboxes/{id}` |
| Ключи | `GET /v1/keys`, `POST /v1/keys`, `DELETE /v1/keys/{id}` |
| Ключи поставщиков | `GET/POST /v1/provider-credentials`, `POST /v1/provider-credentials/{id}/promote`, `DELETE /v1/provider-credentials/{id}` |

Ошибки читаются из конверта `{error: {type, code, message, request_id}}`.
Серверное сообщение, код и идентификатор запроса показываются в красной полосе
под верхней панелью. Если сервер не отвечает, консоль пишет «Сервер не
отвечает» и оставляет на экране последние успешные данные.

Эндпоинт ключей поставщиков может ещё не существовать. На ответ `404` форма
показывает «Сервер ещё не принимает ключи поставщиков» и сохраняет введённые
значения.

## Где живёт ключ

Ключ хранится только в `sessionStorage` этой вкладки под именем
`rox_cloud_key`. Он не попадает в адресную строку, не пишется в журнал и не
выводится в консоль браузера. Кнопка «Выйти» удаляет его. При закрытии вкладки
ключ исчезает; после перезагрузки страницы в той же вкладке подключение
сохраняется.

Название организации и адрес API хранятся в `localStorage`; это не секреты.

## Что показывается как «—»

- Имя ключа: API не возвращает поле `name`, поэтому в колонке «Имя» стоит «—».
- `cost_so_far_usd`: если сервер не прислал ни его, ни `cost_so_far_cents`,
  расход песочницы показывается как «—».
- `expires_at: null`: в колонке «Истекает» стоит «—».
- `last_used_at: null`: «—».
- Поля ключа поставщика (`last4`, `status`, `health`), которых нет в ответе:
  «—».

## Ограничение браузера

Консоль вызывает API из браузера. Если она открыта с одного адреса, а API — с
другого (например, страница на `:8080`, API на `:8787`), API должен разрешить
этот источник заголовками CORS. Если CORS нет, браузер сообщит «Сервер не
отвечает»; это ограничение сервера, а не консоли. Надёжный вариант — отдавать
консоль самим API с того же источника.
