# Автономные программы — пак промптов

Пак промптов для **сквозного автономного исполнения задач** в `rox-one/rox-one`:

**задача → PRD → SPEC → план → субагенты → гейты → PR → CI → merge в main → деплой → живой smoke → отчёт.**

Человеческих approval'ов на пути нет. Останавливают агента ровно четыре класса блокеров:
① нет креды/прав, ② security-вето, ③ угроза необратимого разрушения данных, ④ решение владельца (@agisota, юр./продуктовое — агент готовит ADR и останавливается на этом шаге) — см. `00-orchestrator.md` §2 «Стоп-лист».

*Версия 1.0 · 2026-10-13*

## Как пользоваться

1. **Полный режим (рекомендуется):** скопируй `00-orchestrator.md` целиком как задание агенту и добавь в конце блок `## ЗАДАЧА` (текст, номер тикета или ссылка на issue).
2. **Быстрый режим:** `99-master.md` — компактная самодостаточная версия на одну страницу.
3. Промежуточные артефакты агент кладёт по правилам репозитория: PRD/SPEC — см. `01-prd.md`/`02-spec.md`, решения — в `plans/*/decisions/`.

## Принципы

- **Evidence-first.** Каждый гейт = команда + вывод + SHA ревизии. «Зелёно» без доказательства — красный гейт.
- **Один писатель на область.** Один файл/область — один владелец; параллельность — через worktrees (`~/Projects/rox-worktrees/<slug>`).
- **Ratchet не растёт.** `scripts/test-baseline.json` (knownRed) — потолок; новые красные тесты блокируют слияние.
- **main защищён правилами.** Слияние только через PR; откат — `git revert` или возврат к зафиксированному SHA, force запрещён ([`../plans/lane-process.md`](../plans/lane-process.md)).
- **Внешнее — не код.** Отказ внешнего сервиса (Vercel, провайдер, прод-Cloudflare OPS) фиксируется как внешний и эскалируется владельцу.
- **12 локалей.** Все user-facing строки — через `t()` во все 12 файлов, ключи ASCII-сортировкой ([`../../AGENTS.md`](../../AGENTS.md)).
