# ADR-0023: Каталог скиллов на масштабе 10 000+

- **ID:** `RX-ADR-0023`
- **Status:** Accepted
- **Date:** 2026-10-13
- **Branch:** `perf/program-setup-20261013`
- **Refs:** эпик #1596, [skills-at-scale.md](../../perf/skills-at-scale.md), [process-map.md](../../perf/process-map.md)

RFC 2119: MUST / MUST NOT / SHOULD / MAY.

## Context

Замер на фикстуре (машина под нагрузкой; CPU-время надёжнее wall-time):

| Скиллов | Путь агента (`loadAllSkills`), CPU | Путь панели (`includeOmp`+`includeShadowedOmp`), CPU / wall | Payload списка | Рост RSS |
|---|---|---|---|---|
| 1 000 | 0,52 с | 0,96 с / 5,5 с | 610 КБ | +53 МБ |
| 5 000 | 2,8 с | 4,9 с / 27,7 с | 3 МБ | +170 МБ |
| 10 000 | 7,6 с | 14,3 с / 110 с | 6,1 МБ | +348 МБ |

Всё это синхронно исполняется в главном процессе Electron (server-core работает in-process), то есть замораживает приложение целиком. Причины:

- `readSkillInstructions` делает ~35 синхронных системных вызовов на скилл (realpath + lstat всей цепочки предков дважды); тело каждого SKILL.md читается и хранится в кеше, хотя списку нужны только метаданные.
- `~/.agents/skills` сканируется дважды — как OMP-shared и как global-тир; панель получает ~2× записей (затенённые копии).
- `gray-matter` без опций кеширует каждый разобранный текст навсегда (`matter.cache`).
- `extractSkillPaths` загружает весь каталог на каждое сообщение чата; спавн OMP — тоже.
- Каждое событие вотчера в папке скиллов вызывает полную перезагрузку и пуш всего списка; рендерер игнорирует пуш и перезапрашивает список.
- Ни один список скиллов в рендерере не виртуализирован; меню @-упоминаний без лимита; композер предзагружает иконки всех скиллов.

## Decision

1. **Метаданные отдельно от тел.** Списки и каталог MUST читать только «голову» SKILL.md (до 8 КБ, frontmatter) через отдельный читатель с проверками: `realpath.native` каталога и файла, файл внутри каталога скилла, `O_NOFOLLOW`, `fstat` — обычный файл, совпадение `dev/ino` с разрешённым путём, лимит размера. Полная проверка `readSkillInstructions` (цепочка предков, повторная верификация) MUST остаться для чтения тела (детали скилла, директива агенту).
2. **Один проход на корень.** Каждый физический корень сканируется один раз за обновление; `~/.agents/skills` MUST NOT порождать затенённые дубликаты самого себя.
3. **Без кеша gray-matter.** Все вызовы `matter()` MUST передавать объект опций (отключает неограниченный `matter.cache`).
4. **Упоминания без обхода каталога.** Разрешение `[skill:slug]` MUST искать только упомянутые slug'и (с тем же приоритетом тиров, алиасами коллизий и `allowedSkillSlugs`); сообщение без `[skill:` MUST NOT трогать каталог.
5. **Индекс вне главного потока.** Каталог — инкрементальный индекс (ключ — путь + mtime + size), холодный проход идёт в пуле воркеров (ADR-0024), горячий — только `readdir`/`stat` и перечтение изменившихся голов. Снимок индекса SHOULD сохраняться на диск для мгновенного тёплого старта.
6. **Постраничный API.** RPC `skills:query` (`query`, `offset`, `limit` ≤ 500, фильтры) возвращает `{items, total, revision}`; пуш `skills:changed` несёт `{revision, changed, removed}` и коалесцируется (≥ 250 мс). Полный список MUST NOT уходить в рендерер при каждом изменении.
7. **Поиск прежде списка.** Все списки скиллов в рендерере MUST быть виртуализированы; меню упоминаний показывает не больше 50 совпадений; иконки грузятся лениво для видимых строк.

## Consequences

- Список на 10 000 скиллов — O(видимые строки) в DOM и O(изменения) на диске после первого прохода.
- Синхронный `loadAllSkills` сохраняется для совместимости (expand–contract), но становится дешёвым; пользовательские RPC переходят на асинхронный индекс.
- Безопасность чтения тела не ослабляется; для метаданных TOCTOU-окно закрывается сверкой `dev/ino`.
