# MCP при установке и первый разговор

При создании workspace приложение сохраняет встроенные MCP в обычные папки
`sources/<slug>`. На первом запуске и при следующих запусках `BuiltinMcpStartup`
в фоне устанавливает зависимости поддерживаемых локальных MCP и проверяет
`initialize/listTools`.
Интерфейс и первый разговор не ждут завершения скачивания. Статус `connected`
появляется только после проверки; ошибки сети, отсутствие авторизации и
неподдерживаемая платформа отражаются в статусе источника.
После временных сетевых ошибок фоновые проверки повторяются автоматически:
интервал начинается с минуты и постепенно растёт до пяти минут. После
добавления credentials или готовности runtime проверка запускается снова;
отсутствующие ключи и неподдерживаемые платформы не опрашиваются непрерывно.
При закрытии приложения таймеры и процессы установки останавливаются.

| Интеграция | Подключение и необходимые настройки |
| --- | --- |
| DeepWiki | Публичный HTTP MCP `https://mcp.deepwiki.com/mcp` |
| Context7 | Публичный HTTP MCP `https://mcp.context7.com/mcp`; ключ необязателен |
| Firecrawl MCP | Закреплённый npm-пакет; нужен API-ключ. Существующий API-источник `firecrawl` сохраняется |
| Playwright | Закреплённый npm-пакет и автоматически устанавливаемый совместимый Chromium |
| Telegram MCP | Закреплённый upstream Git commit; нужны API ID, API hash и авторизованная сессия |
| CodeGraphContext | Закреплённый Python-пакет и встроенная локальная графовая БД; проект индексируется при работе с ним |
| [QMD](https://github.com/tobi/qmd) | Закреплённый `@tobilu/qmd`, локальный индекс документов; семантический поиск скачивает локальные модели |
| [Weaviate](https://docs.weaviate.io/weaviate/configuration/mcp-server) | Встроенный HTTP MCP работающей БД Weaviate ≥1.37.1; нужен `WEAVIATE_URL` или явно настроенный MCP URL |
| [Qdrant](https://github.com/qdrant/mcp-server-qdrant) | Закреплённый `mcp-server-qdrant`, локальная БД и FastEmbed; отдельный сервер и облачный аккаунт для локального режима не нужны |
| [Mem0](https://docs.mem0.ai/platform/mem0-mcp) | Официальный облачный HTTP MCP; нужен `MEM0_API_KEY` или настроенная OAuth-авторизация |
| Everything MCP | Windows/Bun; ES CLI устанавливается автоматически, требуется работающий движок Everything |
| Windows Commander MCP | Windows x64; проверенный архив релиза устанавливается автоматически |
| Windows MCP | Windows x64; проверенный исполняемый файл релиза устанавливается автоматически |
| Superpowers | Встроенный пакет навыков; отдельный MCP-процесс не создаётся |
| Understand Anything | Девять встроенных навыков, исходники и помощники закреплённого upstream; полное индексирование/dashboard использует первоначальную установку зависимостей Node/pnpm |

Версии, команды и upstream-ссылки находятся в
`packages/shared/src/sources/builtin-mcp.ts`, SHA256 Windows/ES — в
`builtin-mcp-installer.ts`, снимки навыков — в `resources/skills/SKILLS.lock`.
Ключи и Telegram-сессия берутся из окружения или зашифрованного хранилища
учётных данных и подставляются в память при запуске. Секреты не записываются
автоматически в `config.json`.

QMD `@tobilu/qmd@2.8.3` автоматически получает отдельные настройки и кеш в
папке источника. Его начальная коллекция — включённый локальный Notes vault,
а при отсутствии Notes — пустая папка `sources/qmd/documents`. На запуске
обновляется индекс ключевых слов, без скачивания LLM. Корень workspace с
конфигурациями и историей сессий автоматически не индексируется. Пользовательские
настройки сохраняются; автоматическое обновление не выполняет их shell hooks.
Дополнительные коллекции задаются через
`qmd collection add`, обновляются через `qmd update`, а семантический индекс
создаётся через `qmd embed`; команды используют `--index rox` и те же
`QMD_CONFIG_DIR`/`XDG_CACHE_HOME`, что MCP. Для первого скачивания моделей нужен доступ к
сети; дальнейшие вычисления выполняются локально. Агент проверяет `status`
и использует реально опубликованные `query`, `get`, `multi_get` для работы с индексом.

Qdrant использует официальный пакет `mcp-server-qdrant==0.8.1` и инструменты
`qdrant-store`/`qdrant-find`. По умолчанию локальная база хранится в папке
источника workspace (`QDRANT_LOCAL_PATH`), а embeddings вычисляет FastEmbed
с многоязычной моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`,
поддерживающей русский язык. Модель (~220 МБ) скачивается при
первом запуске и сохраняется в `sources/qdrant/embedding-cache`; её имя закреплено в настройках, загрузкой
файлов модели управляет FastEmbed. Для удалённой БД используются `QDRANT_URL`
и при необходимости `QDRANT_API_KEY`. Локальный путь нельзя одновременно
передавать с удалённым URL или API-ключом. Это отдельное хранилище от индекса
QMD и памяти Mem0.
Одновременные чаты и проверки разделяют один MCP-процесс для локальной базы,
чтобы избежать конфликта файловых блокировок. Последний клиент освобождает процесс.

Для Weaviate приложение настраивает подключение к существующей БД.
`WEAVIATE_URL` принимает адрес БД, например `http://127.0.0.1:8080`; её MCP
находится по `/v1/mcp`. Явно заданный MCP URL сохраняется. На self-hosted
Weaviate требуется `MCP_SERVER_ENABLED=true`; на Weaviate Cloud MCP уже
включён. Ключ `WEAVIATE_API_KEY`, если нужен, передаётся как
`Authorization: Bearer ...` из окружения или зашифрованного хранилища.
Запись на self-hosted БД требует `MCP_SERVER_WRITE_ACCESS_ENABLED=true`.
Weaviate проверяет права пользователя при вызовах инструментов. Его сервер
БД и Docker в этой настройке автоматически не устанавливаются. Без URL
источник ожидает настройки, без успешно проверенного подключения не считается
работающим. [Старый отдельный MCP Weaviate](https://github.com/weaviate/mcp-server-weaviate)
устарел и не устанавливается.

Mem0 подключается к `https://mcp.mem0.ai/mcp`. API-ключ получается в
[Mem0 dashboard](https://app.mem0.ai/dashboard/api-keys) и передаётся как
Bearer token; настроенная пользователем OAuth-авторизация сохраняется.
Без авторизации источник ожидает подключения. Память хранится в облачном
аккаунте Mem0. Приложение не создаёт новые облачные аккаунты автоматически.
Архивированный [Python MCP Mem0](https://github.com/mem0ai/mem0-mcp)
также использовал облачный API и не предоставлял локальную память без аккаунта.
Локальный [Mem0 OSS](https://docs.mem0.ai/cookbooks/companions/local-companion-ollama)
с Ollama — отдельный вариант развёртывания, который эта интеграция не запускает.

Поддерживаемые MCP входят в исходный выбор новых чатов, включая серверы,
ожидающие ключа или установки. Поэтому завершение настройки может подключить
их в уже открытом первом чате. При обновлении существующего workspace новые
источники добавляются в defaults один раз. Выключенные источники, изменённые
конфигурации, сохранённый выбор workspace и явный выбор конкретного чата
сохраняются. Удалённый workspace устанавливает зависимости на своём сервере.

Агент получает общие правила применения интеграций и текущие статусы
источников на каждом ходе, включая OMP. Он использует реальные опубликованные
инструменты по назначению, читает guide источника и не считает наличие
конфигурации доказательством работоспособности. MCP pool восстанавливает
закрытые соединения и истёкшие HTTP-сессии; неопределённо завершившиеся
вызовы не повторяются автоматически.
Причины незавершённой настройки также передаются агенту на последующих ходах.

В первой локальной сессии появляется сохранённое сообщение Rox с тремя
необязательными вопросами: как обращаться к пользователю, с какой задачей
начать и какие предпочтения учитывать. Для этого не вызывается модель.
Маркер на диске исключает повтор после перезапуска, удаления приветственного
чата или смены workspace. На установках с существующими чатами приветствие
не добавляется.

Проверки покрывают создание workspace, выбор defaults, сохранение приветствия,
авторизацию, установку и контрольные суммы, ошибки/отмену фоновой установки,
восстановление MCP после остановки реального stdio-процесса, промпты и упаковку
навыков для Electron/headless.
Последние три регрессионных набора: 342 проверки источников/промптов/RPC,
133 проверки MCP/startup и 302 проверки первого чата/упаковки/i18n —
777 тестов без ошибок. Проверки типов `shared` и `session-tools-core` прошли.
Общий typecheck `server-core` остаётся ограничен двумя прежними TS7016
для деклараций установленного `sharp`; других ошибок этот запуск не показал.

QMD `2.8.3` дополнительно проверен реальным stdio-подключением: список
инструментов и поиск Markdown-фикстуры через lexical query с `rerank=false`
прошли без скачивания GGUF-моделей.

Дополнительно Weaviate `v1.39.8` проверен реальным запуском Linux amd64
релиза с проверкой опубликованной SHA256: `initialize`, список четырёх
инструментов, чтение схемы, запись тестового объекта и поиск через
`weaviate-query-hybrid` с `alpha=0` вернули ожидаемые результаты. Проверка
использовала временную локальную БД без внешнего embedding-провайдера;
семантические запросы требуют настроенного vectorizer или готовых векторов.
Авторизованные вызовы облачного Mem0 без пользовательского ключа не проверялись.

Реальный Qdrant `0.8.1` с выбранной многоязычной моделью установил пакет и
зависимости через uvx. Дальнейший запуск в среде проверки остановился на
загрузке модели с HuggingFace: сетевой прокси ответил `403 Forbidden`.
Поэтому реальный handshake, запись и поиск Qdrant в этой среде не подтверждены;
совместное владение процессом, настройки окружения и восстановление проверены
на MCP subprocess-фикстурах. При первом запуске нужен доступ к загрузке модели
либо заранее заполненный FastEmbed-кеш.
