# Rox Cloud: сайт, кабинет и панель

Дата: 2026-11-22. Ветка: `feat/cloud-byok`. Статус: к реализации.

## 1. Задача

Один продукт из трёх поверхностей с общим языком и оформлением:

- **Сайт** (`/`) представляет продукты Rox Cloud, их состав и цену за час, ведёт кнопкой «Купить» в кабинет без регистрации.
- **Кабинет** (`/console`) даёт выбрать образ, процессор, память, диск, видеокарту и площадку на одном экране, запустить машину, увидеть её состояние, цену и терминал в браузере.
- **Панель дежурного** (`/admin`) показывает клиентов, их балансы, ключи, машины, полный журнал действий и запросов; позволяет пополнить баланс и перевыпустить ключ клиента.

Пользователь: человек, который пришёл с сайта и хочет получить машину за минуту; дежурный, который видит всё происходящее и управляет доступом.

Успех: с главной страницы нажатием «Купить» человек попадает в кабинет с выбранным продуктом, запускает машину, вводит `uname -a` в терминале и видит ответ; дежурный видит этого клиента, его ключ, баланс, машину, действия и запросы.

## 2. Границы

Не делаем: приём карт и Stripe, пароли и регистрацию, организации и роли, создание собственных снимков, гарантированный запуск GPU в приёмке (снимок H100 существует, но тестовый запуск слишком дорог), рабочие столы macOS сверх имеющихся снимков.

Делаем: гостевой вход без регистрации, пробный баланс, управляемые и свои ключи поставщика, реальные снимки Daytona, реальные площадки, терминал через `exec`, полный журнал, пополнение и перевыпуск ключей.

## 3. Цена и режимы

Цена считается по составу машины, в целых центах за час:

```
цена = 10 + 6×cpu + 3×memoryGb + 0,2×diskGb + gpu
gpu: h100 = 300, l4 = 90, a10 = 120, t4 = 60, неизвестная = 120 (за карту)
```

Округление вверх до целого цента. Сервисный сбор при своём ключе поставщика: `max(5, round(цена × 0,15))`.

| Код | Название | Снимок Daytona | cpu / ГБ / диск | GPU | Цена, ¢/ч |
| --- | --- | --- | --- | --- | --- |
| `linux-start` | Старт | `daytonaio/sandbox:0.11.0` | 1 / 1 / 3 | — | 20 |
| `linux-pro` | Разработка | `rox-cloud-medium-2x4` | 2 / 4 / 8 | — | 36 |
| `linux-large` | Большая | `rox-cloud-large-4x8` | 4 / 8 / 10 | — | 60 |
| `windows-start` | Windows Старт | `windows-small` | 1 / 4 / 30 | — | 34 |
| `windows-pro` | Windows Про | `windows-medium` | 2 / 8 / 50 | — | 56 |
| `windows-large` | Windows Большая | `windows-large` | 4 / 16 / 50 | — | 92 |
| `windows-xl` | Windows XL | `windows-xlarge` | 8 / 32 / 100 | — | 174 |
| `gpu-h100` | GPU H100 | `daytona-gpu` | 16 / 100 / 400 | 1×H100 | 786 |

Снимки и доступность — по живому аккаунту Daytona: рабочие оболочки у `daytonaio/sandbox:0.11.0`, `rox-cloud-medium-2x4` и `rox-cloud-large-4x8` в площадке `us`; старые `daytona-small/medium/large` отвечают на команды `/usr/bin/zsh: permission denied` и не продаются. Windows-класс и GPU-кредиты у этого аккаунта недоступны, поэтому эти строки показываются с ценой и пометкой «по запросу», без рабочей кнопки запуска. Продукты несут `available` и `note`; создание по недоступному продукту отказывает до резерва.

Два режима оплаты:

- **managed** — у клиента нет своего ключа поставщика для выбранного провайдера, машина идёт на платформенном ключе Rox, кошелёк платит полную цену. Так работают гости и новые клиенты.
- **byok** — у клиента есть свой ключ, машина идёт на нём, кошелёк платит только сервисный сбор. Железо клиент оплачивает поставщику напрямую.

В ответе о машине и в счёте видно режим, цену часа и сервисный сбор. Сайт показывает полную цену с пометкой «или только сервисный сбор со своим ключом».

Пробный баланс гостя: 2000 ¢ (20,00 $). Ограничения гостя: 1 машина одновременно, не больше 16 ядер, месячный потолок 2000 ¢, срок жизни не больше 24 часов.

## 4. Покупка без регистрации

`POST /v1/guest` (публичный, включается `ROX_GUEST_ENABLED=1`, не чаще 5 раз в час с одного адреса) создаёт клиента `guest-…`, выдаёт ключ API и кладёт 2000 ¢. Ответ:

```json
{ "object": "guest", "tenant": { "id": "guest-…", "name": "Гость" },
  "api_key": "rox_sk_live_…", "balance_cents": 2000 }
```

Ключ живёт только в `sessionStorage` вкладки. Сайт ведёт на `/console?plan=<код>&guest=1`; кабинет сам создаёт гостя, если ключа нет, и убирает `guest` из адреса. Если гостевой вход выключен, кабинет показывает форму ключа с объяснением.

Платформенный ключ Daytona задаётся `ROX_PLATFORM_DAYTONA_KEY` (запасной — `DAYTONA_API_KEY`) и никогда не покидает сервер. Каталог сообщает только доступность managed: `managed_providers: ["daytona"]`.

## 5. Образы и площадки

Daytona собирает машину из снимка; снимок несёт ресурсы. Поэтому «образ» в кабинете — это снимок с его cpu / памятью / диском / GPU. Живой список отдаёт `GET /v1/providers/:id/images`, который для Daytona читает `GET /snapshots` его ключом (своим или платформенным) и отдаёт только активные снимки:

```json
{ "object": "list", "provider": "daytona", "data": [
  { "id": "daytona-medium", "name": "daytona-medium", "label": "Linux · Разработка",
    "os": "linux", "cpu": 2, "memoryGb": 4, "diskGb": 8, "gpu": null, "state": "active" } ] }
```

Площадки Daytona из живого `GET /regions`: `us` (общая) и `us-west-4` (выделенная). Тело создания принимает `region`; адаптер передаёт его как `target`, если поле задано. Если площадка не задана, поставщик выбирает сам.

Ползунки cpu / памяти / диска не выдумывают ресурсы: они выбирают ближайший снимок из списка и показывают его точные значения. Если точного совпадения нет, показывается ближайший и подпись «точного образа нет, ближайший». Свой снимок вводится именем в дополнительном поле.

## 6. Терминал

`POST /v1/sandboxes/:id/exec` принимает `{ "command": "…", "cwd": "/root", "timeout_sec": 15 }` и возвращает `{ "stdout": "…", "stderr": "…", "exit_code": 0 }` — та же snake_case-оболочка, что у остальных ответов API. Кабинет рисует терминал: приглашение `daytona@<короткий id>:<каталог>$` (домашний каталог `/home/daytona`; `/root` пользователю недоступен), история команд стрелками, `Ctrl+L` — очистка, кнопки «Копировать», «Очистить», «Развернуть».

Каждая строка выполняется отдельно; каталог хранится в состоянии терминала. `cd <путь>` выполняется как `cd <путь> && pwd`, и приглашение меняет каталог. `clear` очищает экран, `help` печатает подсказку. stdout и stderr показываются разными цветами, код выхода больше нуля — красной пометкой. Это честная эмуляция поверх `exec`, а не постоянный PTY.

## 7. Кабинет

Маршруты:

- `/console` — «Продукты»: пресеты, образ, площадка, срок жизни, итог с ценой и кнопкой «Запустить».
- `/console/machines` — список машин.
- `/console/machines/:id` — машина: состав, цена, срок, терминал, файлы, стоп и удаление.
- `/console/invoice` — счёт и CSV.
- `/console/keys` — ключи клиента.
- `/console/providers` — ключи поставщиков, возможности, добавление и удаление.
- `/console/journal` — журнал действий и CSV.

Один экран конфигуратора: слева пресеты и образы, в центре ресурсы и площадка, справа карточка итога с ценой часа, резервом за срок и остатком после запуска. Всё пересчитывается сразу. Запуск ведёт на карточку машины с открытым терминалом.

## 8. Панель

Маршруты и содержание:

- `/admin` — обзор: клиенты, баланс, резерв, машины, ключи, платформенный ключ, последние действия.
- `/admin/clients` и `/admin/clients/:id` — клиенты, баланс, лимиты, ключи, машины, действия: пополнить, перевыпустить ключ, изменить потолки.
- `/admin/machines` — все машины с фильтрами, остановка.
- `/admin/keys` — клиентские ключи с балансом владельца и ключи поставщиков без секретов.
- `/admin/logs` — два журнала: действия (с фильтрами) и запросы (метод, путь, код, время, клиент, последние 4 символа ключа).
- `/admin/support` — обращения, происшествия, злоупотребления.
- `/admin/security` — рубильник.

Пополнение: `POST /v1/admin/tenants/:id/credit` (уже есть). Перевыпуск: `POST /v1/admin/tenants/:id/rotate-key`, отзывает все ключи клиента и возвращает новый секрет один раз. Старый ключ после этого получает 401.

## 9. API

Новые и изменённые маршруты:

| Метод и путь | Что делает |
| --- | --- |
| `GET /v1/catalog` | продукты с ценами, режимы, площадки, `managed_providers` |
| `GET /v1/providers/:id/images` | снимки/образы доступные этому клиенту |
| `POST /v1/guest` | гостевой клиент, ключ и пробный баланс |
| `POST /v1/admin/tenants/:id/rotate-key` | новый ключ, старые отозваны |
| `GET /v1/admin/keys` | клиентские ключи с балансом |
| `GET /v1/admin/requests` | последние запросы API |
| `GET /v1/admin/audit?tenant=&action=&since=&limit=` | фильтры журнала |
| `POST /v1/sandboxes` | принимает `region`; считает цену и режим |
| `GET /v1/sandboxes/:id` | отдаёт состав, режим, цену, площадку |
| `POST /v1/sandboxes/:id/exec` | принимает `cwd` и `timeoutMs` |

Машина в ответе дополняется:

```json
{ "spec": { "os": "linux", "cpu": 2, "memoryGb": 4, "diskGb": 8,
            "snapshot": "daytona-medium", "region": "us", "ttlSec": 3600 },
  "billing": { "mode": "managed", "rate_cents_per_hour": 36,
               "retail_cents_per_hour": 36, "service_fee_cents_per_hour": 5 } }
```

Каждая машина хранит свою ставку; счётчик, резерв и расчёт при остановке используют её, а не одну общую. При перезапуске ставка, режим и площадка восстанавливаются из состояния.

## 10. Общий фронтенд

Новое приложение `apps/cloud-web`: SolidJS + Vite + TypeScript, маршруты `/`, `/console`, `/admin`, общие токены и компоненты. Сборка кладётся в `apps/cloud-api/public/app`; сервер отдаёт её на `/`, `/console/*`, `/admin/*` и `/assets/*`, API остаётся первым. Старые `apps/cloud-site`, `apps/cloud-console`, `apps/cloud-api/public/admin.html` после приёмки удаляются.

Оформление: светлое, компактное, шрифт `Rox Mono Typeface` везде; фон `#f5f6f8`, поверхность `#ffffff`, текст `#161a1f`, тихий `#5e6876`, граница `#e2e5ea`, акцент `#2f5bea`, успех `#16805a`, предупреждение `#a86400`, ошибка `#b42318`, тёмный терминал `#101418`. Радиусы 10 и 16, тени мягкие, движение 140–180 мс, `prefers-reduced-motion` уважается. Сайт шириной 1180, кабинет с боковым меню 232, панель 224. На узком экране меню становится верхней лентой, таблицы — карточками.

Доступность: подписи у полей, фокус виден, клавиатура работает, контраст не ниже 4,5:1, у иконок есть текстовые подписи.

## 11. Отказы

- Гостевой вход выключен или исчерпан лимит: форма ключа с объяснением, без ложного успеха.
- Нет платформенного ключа: запуск managed отвечает `capability_unavailable`, кабинет ведёт на «Поставщики».
- Список снимков не получен: показываются продукты из каталога с пометкой «список образов недоступен».
- Создание не удалось: резерв возвращается, ошибка показывается в карточке, машина не появляется.
- Баланса мало: кнопка запуска выключена, рядом сумма нехватки и «Пополнить».
- Терминал: stderr и код выхода видны, ошибка соединения не прячется.
- Панель: ошибки показываются строкой с номером запроса; старые ключи после перевыпуска получают 401.

## 12. Приёмка

1. Сайт: продукты с ценами, «Купить» ведёт в кабинет, вёрстка на 1365 и 390 без горизонтальной прокрутки.
2. Гость: ключ создан, баланс 20,00 $, машина `linux-pro` запущена, `uname -a` в терминале вернул ядро, остановка и удаление прошли, счёт показывает списание.
3. Своя машина: `region` сохранён и виден; снимок с GPU виден в списке, запуск не тестируется.
4. Панель: клиент, ключ, баланс, машина, действия и запросы видны; пополнение меняет баланс; перевыпуск отзывает старый ключ (401) и выдаёт новый (200).
5. Код: тесты API, общих пакетов и поставщиков зелёные; сборка `apps/cloud-web` и `tsc` без ошибок; дым зелёный.
6. Секреты: ни один ключ поставщика или мастер-ключ не появляется в HTML, JS, журнале или ответах; ключ клиента только в `sessionStorage`.

## 13. Решения после независимого ревью

- **Цена считается по разрешённому снимку, а не по полям вызывающего.** Создание принимает `product` (код из таблицы) или `snapshot`; сервер находит снимок в живом списке провайдера и берёт его cpu / память / диск / GPU. Поля `cpu`, `memoryGb`, `diskGb`, `gpu` в теле служат только проверкой: расхождение с снимком — `invalid_request`. Снимок `daytona-gpu` всегда стоит 786 ¢/ч, даже если в теле просят 1 ядро. Неизвестный снимок — отказ до резерва.
- **Гостевой ключ не получает `keys:write`.** Его области: `sandboxes:read`, `sandboxes:write`, `billing:read`. Пополнение баланса требует `billing:write` и доступно только дежурному; гость не может начислить себе деньги. Лимит 5 гостей в час считается по адресу клиента, который передаёт сервер (`server.requestIP`), а не по ключу.
- **Лимиты гостя живут у клиента, а не только глобально.** У клиента есть профиль `guest` с 1 машиной, 16 ядрами, 2000 ¢ в месяц и сроком не больше 24 часов. Проверка идёт в `beforeCreate`; PATCH лимитов дежурного меняет и одновременность, и ядра, и месячный потолок. Тесты: вторая машина, 17 ядер, TTL 86401 — отказ.
- **Срок жизни исполняется.** Каждые 30 секунд сервер останавливает машины с истёкшим `expiresAt` через обычный путь остановки и рассчитывает плату. При восстановлении после падения незавершённые записи сначала рассчитываются по ставке за прошедшее время, затем помечаются `failed`; машина у Daytona сама останавливается через 15 минут. Идентификатор поставщика между перезапусками не сохраняется — это записанное ограничение, а не обещание.
- **Счёт хранит состав машины.** Строка счёта (usage) получает снимок, режим, ставку, розничную цену, сервисный сбор, начало и остановку; остановка обновляет сумму и время. Удаление машины не стирает строку счёта.
- **Журнал запросов — у входной двери, с момента запуска.** Пишутся метод, путь без строки запроса, код, длительность, клиент, последние 4 символа ключа и номер запроса; тела и заголовок Authorization не пишутся. Кольцо на 500 строк живёт в памяти, это подписано в панели; полный журнал действий (audit) по-прежнему сохраняется на диск.
- **Одна оболочка JSON.** Запросы создания — camelCase (`memoryGb`, `ttlSec`), оболочки ответов — snake_case (`created_at`, `exit_code`, `api_key`). Секрет ключа и у гостя, и при создании ключа называется `api_key`. OpenAPI описывает все новые маршруты и эту оболочку.
- **Приёмка без платных запусков.** Контрактные тесты с поддельным провайдером (снимки, создание, exec, остановка, удаление, rotate 401/200) — обязательные; живой Daytona — отдельная проверка `ROX_LIVE_DAYTONA=1`. Дым проверяет `/docs`, `/console`, `/admin`, `/v1/admin/tenants`; старые `.html` и `/admin/*` API удалены в том же коммите. Опечатка «vue-независимая» читается как «сборка `apps/cloud-web`».
