# Golden Gate: подробные требования к ROX

Дата: 2026-09-14. База сравнения: `22c8b89858f8c41d3f687f13d49a31b55045c146`.
Этот документ дополняет [SPEC.md](SPEC.md). Инвентаризация основана на чтении кода. Наличие компонента, обработчика или теста не означает, что экран уже проверен визуально либо действие успешно выполнено в Electron. Статусы фактических проверок ведутся отдельно в [QA-MATRIX.md](QA-MATRIX.md).

## 1. Результат и ограничения

ROX должен ощущаться как компактная рабочая среда macOS: постоянные ориентиры, ясный фокус, короткие переходы и единая типографика. Основная задача — работать с несколькими агентами, документами и инструментами без потери контекста. Переключение сервиса меняет контекст навигации, а раскладка сохраняет рабочие объекты.

Фактическая платформа — Electron 39, React 18, Jotai, Radix и motion (`apps/electron/package.json`, `apps/electron/src/renderer/App.tsx`). SwiftUI — ориентир поведения; перенос приложения на SwiftUI не входит в эту итерацию. Сохраняются существующие API, permission policy, локальные/удалённые рабочие пространства, темы, импорты и интеграции. Нельзя подменять отсутствующую runtime-возможность декоративной кнопкой с сообщением об успехе.

Обязательный охват: 19 семейств navigator в parser, 17 явных ветвей `MainContentPanel`, 22 страницы настроек, оболочка, onboarding, workspace wizard, инспекторы, меню, диалоги, rich content, встроенные поверхности и вспомогательные окна. Полные адреса и исключения приведены в [SCREEN-MATRIX.md](SCREEN-MATRIX.md). Механический перечень всех исходных TSX-компонентов и объявленных props находится в [INVENTORY.json](INVENTORY.json); он включает компоненты, чья runtime-достижимость ещё не установлена.

## 2. Пользовательские сценарии

1. Начать сессию, прикрепить источник/файл/навык, выбрать модель и режим доступа, получить ответ, просмотреть результат и повторить действие без повторной настройки.
2. Сравнить четыре или шесть рабочих объектов, изменить ширины/высоты, перейти к соседнему объекту клавиатурой, временно увеличить один объект и вернуться к прежней геометрии.
3. Перейти из чата к заметке, задаче, странице или процессу; сохранить связь с исходным материалом и возврат к месту работы.
4. Увидеть требующее решения событие, открыть соответствующую сессию/разрешение, закончить действие; обычные статусы не мешают чтению.
5. Подключить сервис либо исправить недоступное подключение с понятной причиной; импорт всегда имеет предпросмотр и явный момент применения.
6. Открыть данные устройства, увидеть происхождение и актуальность показателей, закрыть панель без продолжения фонового опроса.

## 5. Геометрия и сохранение состояния

`PanelStackContainer.tsx` в базовой версии строит горизонтальную flex-полосу, а compact-ветка оставляет navigator и focused detail. `packages/core/src/platform/workbench/types.ts` содержит группы вкладок с `proportion`, но не двумерное дерево. Новый слой геометрии должен быть совместим с этим состоянием; существующий route нельзя переписывать при resize.

Минимум для каждой панели: стабильный `instanceId`, route, active entity view, dirty, last focused, доступность. Для раскладки: mode, порядок panel IDs, веса колонок/рядов, focused panel ID и предыдущая геометрия для возврата из focus. Персистентное состояние привязано к workspace; скрытая панель не должна отдавать клавиатурный фокус. Ошибочный JSON либо удалённый объект дают безопасное восстановление с сохранением доступных панелей.

`auto` выбирает раскладку по числу объектов и доступной площади, сохраняя пользовательские размеры внутри выбранного режима. `grid-2` и `grid-3` означают 2 и 3 колонки; при четырёх и шести панелях получается два ряда. При пяти панелях незанятая ячейка не считается рабочим объектом. Одинарная панель не получает пустые соседи. Для большего числа объектов допускаются дополнительные ряды; нельзя обрезать седьмую панель. Явный режим сохраняется при изменении ширины окна; при недостатке места рабочая область прокручивается либо временно показывает один фокусированный объект с доступным возвратом.

Размеры контента определяются читаемостью, а не уменьшением масштаба шрифта. Базовый `PANEL_MIN_WIDTH=440` требует проверки отдельно для чата, таблицы, браузера и заметки. В редакторе должен оставаться полезный текстовый столбец; встроенные rails заметок сворачиваются раньше самого документа. Соседние разделители имеют одинаковые hit zones. Двойной клик может выравнивать размеры только если это действие явно обозначено и доступно клавиатурой.

Проверяемые данные состояния: черновик с кириллицей/emoji; selection в editor; scroll в середине длинного чата; фильтр коллекции; выбранная карточка; активная вкладка Project; viewport canvas; browser URL/history; terminal process ID; открытый инспектор. Для перезапуска восстанавливаются только предусмотренные хранилищем данные: пароли, временные grants и внутренний DOM selection нельзя обещать сохранять без существующего контракта.

## 6. Визуальная система и текст

Golden Gate использует спокойные нейтральные поверхности и тёплый акцент для выбранного объекта/основного действия. Цвет ошибки остаётся отдельным от акцента. Никакой фоновый декоративный эффект не должен снижать контраст текста. Единственная система токенов работает в `packages/ui/src/styles/index.css` и `apps/electron/src/renderer/index.css`; legacy aliases сохраняются до миграции потребителей.

| Роль | Предлагаемый диапазон | Семантика |
|---|---|---|
| UI / списки | 12–13 px, line-height ≥1.35 | `--font-ui`, системный font stack по выбору пользователя; одинаковая плотность в sidebar/settings/menus. |
| Основной текст | 14–15 px, line-height 1.5–1.65 | `--font-chat` или общая content role; перенос без горизонтальной прокрутки обычных абзацев. |
| Заголовки | 16–20 px, без избыточного веса | Реальные уровни h1–h3; не превращать каждый раздел настроек в отдельный большой hero. |
| Code / terminal / данные | 12–13 px, tabular numerals где нужно | `--font-mono`/terminal; литералы не получают смысл обычной ссылки. |
| Подписи / метаданные | 11–12 px | Вторичный контраст остаётся читаемым; важные ошибки не выводятся только мелкой подписью. |

Смысловые акценты: `<strong>` для важной мысли, `<a>` для перехода, `<code>` для буквального значения, `<mark>` для совпадения/выделения. Пунктирное подчёркивание означает пояснение с доступным tooltip/popover, а не ссылку. Подчёркнутая ссылка имеет hover/focus/visited при необходимости; цвет сам по себе не кодирует действие. Не применять жирный шрифт ко всему абзацу. В search highlights и annotations сохраняются вложенная разметка, selectable text и корректные hit targets.

Размеры компонентов уточняются визуальной проверкой: одна шкала отступов 4/8/12/16/24; header 32–40 px; pointer target ≥28 px, touch ≥44 px. Основной текст соответствует контрасту ≥4.5:1, крупный текст и значимые границы/индикаторы ≥3:1. Ошибка/selection/dirty отражаются не одним цветом. Масштаб приложения 80/100/125/150% не скрывает управление.

## 7. Статусы, предложения и диагностика

Статус всегда привязан к конкретному событию и объекту. Счётчики активных задач/approvals могут агрегироваться, но пользовательское сообщение остаётся одним. Отмена не показывается как успех. Действие из статуса фокусирует нужную панель или существующий approval flow. История подробностей находится в соответствующем инспекторе/журнале, не в постоянно растущем заголовке.

Предложение навыка/процесса имеет четыре обязательных свойства: причина, целевой объект, явное действие и отказ. Начальная политика: максимум одно предложение за раз, cooldown для одной сущности, отказ действует минимум до смены существенного контекста. Точные интервалы — конфигурация и эксперимент E06, не необратимая логика. Сохранение создаёт сначала reviewable draft через существующий редактор. Если обработчик отсутствует, предложение не показывается.

Диагностика не равна странице Runtime Settings. Чип сообщает нейтральную идентичность устройства/соединения и открывает компактную панель: актуальность снимка, версия/платформа, доступные CPU/memory/process/runtime показатели, last error, действие обновления. Для удалённого workspace ясно, чьё устройство измеряется. Первый запрос выполняется при открытии; следующий после завершения предыдущего и только пока панель/окно видимы. Недоступный метод bridge, timeout и отказ отображаются по-разному. Не собирать секреты, переменные окружения или полный process command line ради визуального индикатора.

## 9. Границы поставки и трассировка

Реализация ведётся по пяти текущим направлениям: панели, навигация, визуальные токены/примитивы, диагностика, статусы/предложения. Это основа, а не доказательство законченного редизайна каждого сложного экрана. Screen-specific доработки, реальные native проверки и измерения вынесены в отдельные issues.

[issues.json](issues.json) содержит 25 задач с ID, приоритетом, зависимостями, scope, Definition of Done, статусом покрытия и необходимыми доказательствами. Координатор опубликовал задачи в GitHub; точный маппинг — [ISSUE-LINKS.md](ISSUE-LINKS.md), родитель — [#541](https://github.com/rox-one/rox-one/issues/541). Публикация задачи не означает её выполнение. [QA-MATRIX.md](QA-MATRIX.md) задаёт сценарии и уровни доказательств. Любой не выполненный gate остаётся открытым даже при успешной сборке renderer.
