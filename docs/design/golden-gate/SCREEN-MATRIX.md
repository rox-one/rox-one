# Golden Gate: матрица экранов, свойств и состояний

База: `22c8b89858f8c41d3f687f13d49a31b55045c146`. Дата инвентаризации: 2026-09-14.

**Уровень доказательства этого документа — C: чтение исходного кода.** Таблицы фиксируют обнаруженные entry points, структуры и обработчики; визуальный вид, фактическую работоспособность RPC и прохождение сценариев они не подтверждают. Колонки требований описывают целевой результат. Runtime-артефакты и фактические результаты добавляются в `QA-MATRIX.md` либо отчёт координатора.

Чтобы пути оставались проверяемыми и таблицы читались, ниже используются префиксы: `R = apps/electron/src/renderer/`, `S = apps/electron/src/shared/`, `U = packages/ui/src/`, `C = packages/core/src/`. Это точные относительные пути от корня репозитория. Полный машинный индекс исходных TSX-файлов, экспортов и объявленных props — `INVENTORY.json`.

## Обязательный контракт состояний

Каждая строка экранов наследует **все** правила E/L/X/P/K/R, даже если в существующем коде отдельное состояние ещё отсутствует. Строка с отсутствующим состоянием — требование на реализацию, не «пройдено».

| Код | Состояние | Требование ко всем экранам |
|---|---|---|
| E | Empty / not found / no matches | Различать отсутствие данных, отсутствие выбора, отсутствие совпадений и удалённый объект. Одна понятная основная команда; активный фильтр можно очистить. Не показывать ложную пустоту во время загрузки. |
| L | Loading / saving / running | Сохранять геометрию, старые пригодные данные и ввод. Индикатор относится к конкретной области. Повторный submit недоступен пока идёт запрос; отмена — если поддерживается операцией. |
| X | Error / offline / partial / stale | Человеческое сообщение, локальный retry и сохранённый черновик. Частичные данные помечены, а не выброшены. Runtime error не маскируется пустым списком либо success toast. |
| P | Permission / auth / capability | Показать причину и существующий путь подключения/разрешения. Grant, approval и запись требуют явного действия. Disabled control имеет объяснение; feature flag off не обещает доступную возможность. |
| K | Keyboard / focus / assistive tech | Полный tab order, заметный focus, корректные button/link/form roles. Esc закрывает верхний слой и возвращает фокус. Меню не требуют hover, tooltips доступны фокусом. Работающий editor/terminal сохраняет собственные сочетания. |
| R | Responsive / scale / theme | Проверка 375/768/1280/1800 px, compact panel и масштаб 125/150%; основной контент не пропадает за toolbar. Для таблиц/кода допустима локальная прокрутка. Контраст и hit targets сохраняются в light/dark/high contrast. |

Одинаковая карточка не должна бесконтрольно размножаться при каждом состоянии. Inline ошибки используются рядом с полем, глобальные — у поверхности. Успех не заменяет введённый пользователем текст. Критерии i18n, motion, native boundaries и производительности действуют поверх всех строк (`GG-R11`–`GG-R15`).

## Оболочка и маршруты

Источник истины маршрутов: `S/routes.ts` (builders), `S/route-parser.ts` (19 navigator families), `S/types.ts`, `R/contexts/NavigationContext.tsx`. Центральный renderer: `R/components/app-shell/MainContentPanel.tsx` (17 явных семейств). Путь с заданным ID проверяется также после удаления объекта и после перезапуска.

В `routes.ts` обнаружено **35 view builders и 10 action builders**; варианты вроде `sourcesMcp` и `sources({type:'mcp'})` ведут к одному экранному семейству. Их точные выражения сохранены в `INVENTORY.json`. Action route не считается отдельным экраном, но должен сохранить результат и существующий permission flow:

| Action route | Свойства / эффект | Приёмка |
|---|---|---|
| `action/new-session` | `input`, `name`, `send`, `status`, `label`, `project` | Preview draft и явный send не смешиваются; новая сессия получает заданные metadata; input с Unicode проходит encoding. |
| `action/rename-session/{id}` | `name` | Validation/dirty/error; rename обновляет все видимые ссылки на объект. |
| `action/delete-session/{id}` | Target session | Существующее подтверждение; восстановление/закрытие панели согласовано с удалением. |
| `action/flag-session/{id}`, `action/unflag-session/{id}` | Flag toggle | Списки/board/filter обновляются без перезагрузки всей коллекции. |
| `action/oauth/{sourceSlug}` | Source OAuth | Waiting/cancel/error/expired; привязка к нужному source и возврат фокуса. |
| `action/add-source`, `action/delete-source/{sourceSlug}` | Add/delete UI | Нельзя пропустить existing permissions/confirmation; source references сохраняют понятный unavailable state. |
| `action/set-mode/{sessionId}` | `mode` = существующий PermissionMode | UI отражает фактический mode и respawn contract; не auto-escalate от навигации. |
| `action/copy` | `text` | Точный текст в clipboard; успешный feedback только после результата API. |

Совместимость: `settings/toolchain` → `settings/runtime`, `settings/preferences` → `settings/context`. Parser поддерживает правую панель через `sidebar`: `history`, `files`, `files/{path}`, `git`, `browser`, `context`, `none`. Наличие `history` в parser — только контракт сериализации; отдельный действующий history host этим аудитом не подтверждён. Не превращать ветви внутреннего `convertParsedRouteToNavigationState` в обещание новых публичных URL: `parseRoute` принимает только известные compound prefixes либо `action/*`.

## Подтверждённые чтением кода пробелы и ограничения охвата

1. Parser и builders принимают `terminal/{id}` и `cloud-run/{id}`, но `MainContentPanel` базовой версии не имеет их явных ветвей. Реальные terminal dock и cloud settings/chip существуют. Требуется trace входа и устранение немого fallback (`GG-018`).
2. `TasksPage` и `MeetingsPage` подключены без route-selected ID в `MainContentPanel`; наличие parser detail не доказывает правильную фокусировку объекта (`GG-014`, `GG-015`).
3. `teamchat` объявлен недоступным; SiYuan graph/mindmap — условные возможности. Нельзя считать их полноценными native screens без подключения (`GG-009`, `GG-012`).
4. Memory живёт в navigator, Notes имеет собственные внутренние rails, Knowledge является отдельной системой. Унификация sidebar должна учитывать эту фактическую архитектуру (`GG-002`, `GG-010`, `GG-013`).
5. `PanelContribution.slot` имеет activity/navigator-primary/navigator-secondary/inspector/bottom/status; наличие слота не означает наличие core UI во всех слотах. `PanelHost` отфильтровывает session-harness contributions, которые рисует `InspectorHost`. Проверить отсутствие дублирования (`GG-004`).
6. `ModeBar.tsx`/`modes-seed.ts` — отдельный capability-gated механизм; `WorkspaceSurfaceHost` базовой версии выставляет `modeRegistry:false` и `statusBar:false`. Не смешивать зарегистрированный mode со всегда видимой rail destinations.
7. Исходные файлы playground, viewer и вспомогательных компонентов входят в механический индекс, но не становятся пользовательскими route. Новый отдельный route нельзя выводить только из имени `*Page.tsx`.
8. Общие CSS изменения покрывают часть внешнего вида, но не доказывают правильные labels, native visibility, form validation и все состояния 22 settings. Эти проверки остаются отдельными задачами.
