# Golden Gate — требования к реализации ROX

Дата: 2026-09-14. База: `22c8b89858f8c41d3f687f13d49a31b55045c146`.
Запрос владельца: аудит, подробные требования и issues, параллельная реализация, функциональная и визуальная проверка.

## Целевой результат
Компактное приложение macOS с единой панелью сервисов, контекстной навигацией и устойчивой рабочей областью. Все существующие возможности сохраняются. Задача включает изменение рабочего кода, не только макет.

## Решения и границы
1. Сохраняем Electron, React 18, Jotai, Radix, motion и текущие маршруты. Полная перепись на SwiftUI не нужна для заданного результата. Эффекты SwiftUI служат ориентиром поведения, не доказательством нативной реализации.
2. Стабильная панель сервисов: агенты, заметки, память, браузер, автоматизация; остальные зарегистрированные сервисы доступны через дополнительное меню; настройки закреплены отдельно.
3. Контекстный сайдбар показывает объекты и действия активного сервиса. Клик по сервису фокусирует открытую панель этого сервиса; смена фокуса сохраняет идентичность панелей и черновики.
4. Геометрия панелей хранится отдельно от маршрутов: режимы `auto`, `columns`, `grid-2`, `grid-3`, `focus`. 4 панели образуют 2×2; 5–6 — 3×2. Изменение размера по X и Y, клавиатурой и указателем; восстановление после перезапуска. При недостатке места допускается прокрутка, а не уменьшение текста до нечитаемого.
5. Существующие типы panel/lane/tab и сохранённые маршруты совместимы. Неактивные панели не получают фокус; скрытые тяжёлые активности должны приостанавливаться по их контрактам.
6. Единые семантические токены: нейтральные поверхности, сдержанный тёплый акцент Golden Gate, шрифты системы, компактный ритм. Именованные пользовательские темы сохраняют приоритет. Минимальные цели указателя 28px, touch 44px.
7. Анимации короткие (120–220ms), преимущественно opacity/transform. Не анимировать blur, не добавлять постоянные декоративные GPU-циклы. Учитывать reduced motion, reduced transparency и повышенный контраст.
8. Статус в заголовке: один актуальный сигнал, дедупликация, сообщения успешного завершения исчезают, действия/ошибки доступны до решения. Live region polite, без перехвата фокуса.
9. Подсказки применить/сохранить навык или процесс используют существующие реальные действия. Явное согласие на действие, dismiss и cooldown; никаких автоматических записей или запусков от показа подсказки.
10. Чип устройства открывает диагностическую панель. Данные реальные; неподдерживаемые метрики обозначаются как недоступные. Нет фонового опроса при закрытой панели; скрытие окна прекращает обновления. Диагностика только читает состояние и не меняет процессы/launch agents.
11. Все пользовательские строки через `t()`; новые ключи во всех 12 существующих локалях в ASCII-порядке (включая ar и ko, отсутствующие в старом списке AGENTS.md). Паритет переводов обязателен.
12. Общие правила текста: strong для смыслового акцента, настоящие ссылки со стандартным фокусом/подчёркиванием, пунктир только для пояснения, code для литералов, mark для поиска/выделения; значение не кодируется одним цветом.
13. Пустой одиночный каталог сессий занимает рабочую область до выбора записи. Не показывать безымянную вкладку и несколько постоянных пустых колонок. Инспектор новой установки свёрнут; существующие явные настройки сохраняются. Для узкого desktop-окна viewport содержимого имеет минимум 320px с прокруткой оболочки при нехватке места, без перезаписи предпочтений ширины.
14. В каждом workspace восстанавливаются собственные ширины и раскрытые секции. Незаконченный resize отменяется до восстановления нового состояния. Чтение предпочтений ничего не записывает.
15. Запоздалый ответ документа, встречи или каталога не заменяет новую выбранную сущность. Подтверждение сохранения не очищает более свежий черновик. Скрытый retained editor не получает фокус и не оставляет активный portal поверх другого сервиса.

## Разделение работы
- Панели: geometry/storage, PanelStackContainer, PanelSlot, resize hooks; без AppShell и локалей.
- Навигация: ActivityRail, LeftSidebar, nav-destinations, service-navigation; интеграция AppShell у координатора.
- Дизайн: shared/renderer CSS, примитивы, семантика текста; без панельного контейнера.
- Диагностика: новый чип/панель и узкая безопасная API-граница.
- Статусы/подсказки: общие компоненты и чистая политика показа; интеграция у координатора.
- Инвентаризация: PRD, матрица экранов, задачи и QA.

## Проверка
Исходная версия запускается из отдельного immutable checkout. Различаем проверку кода, браузерный стенд с данными-примерами, реальный сервер и Electron/macOS. Для каждого результата указываем фактически достигнутый уровень. Обязательны сборка renderer, проверки затронутых типов и поведения, паритет i18n, навигация/панели/перезапуск, клавиатура, состояния ошибок и визуальные снимки. Непроверенный native/macOS сценарий остаётся явно открытым условием приёмки.
