# UI-001: сохранение внешней ссылки при интеграции в main

Владелец: текущий агент, одна рабочая копия `fix/ui-001-main-integration-20261003-7`. Вход main: `635fc495d02c3fe1380740444cb90cf4fbdb58d9`. Пользователь разрешил полный ремонт исходников, публикацию в GitHub и merge main 2026-10-03.

Неизвестная или повреждённая ссылка должна сохранять исходный адрес и открывать существующую локализованную поверхность `route-unavailable`. Это действует при обычной навигации, deep link, восстановлении одного/нескольких панелей, reload, истории и смене рабочего пространства. Восстановление адреса действия не выполняет действие. Валидные маршруты сохраняют свои поверхности и выбор сущности; отложенная навигация сохраняет query и параметры открытия панели. Компактный режим показывает сообщение о недоступной ссылке.

Существующие исправления main для удалённых source/skill, гонок callbacks и валидных размеров сохраняются и проверяются. Nullable API парсера и документированные legacy degradation-контракты сохраняются; новый runtime resolver исключает подмену внешней ссылки чатами.

Исходные Requirements, DoD, Full functional verification и Test method задач UI-001.1/UI-001.2 сохранены дословно в acceptance-contract.json. Проверки Chromium используют реальные NavigationProvider, panel atoms, URL/history и извлечённый из исходника MainContentPanel с заменёнными leaf UI и transport fixtures. Эти проверки не являются установленной Win/macOS либо hosted приёмкой. FullDoD остаётся false до наблюдения всей исходной матрицы и canonical backend readback.
