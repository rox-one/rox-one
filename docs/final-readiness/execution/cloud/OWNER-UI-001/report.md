## Новые исправления и доказательства

1. **Восстановление после первоначальной ошибки.** Реальные SourceInfoPage и SkillInfoPage могли оставаться в состоянии ошибки после появления сущности или успешного обновления. MainContentPanel теперь сначала определяет присутствие выбранной сущности, подписывается до чтения и отменяет устаревшие запросы. Позднее корректное событие восстанавливает карточку на том же маршруте. Четыре сценария не проходили до изменения; после исправления проходят.
2. **Правильный каталог навыков.** Серверный GET учитывает рабочую директорию, project и OMP; CHANGED вызывает `loadAllSkills(root)` без этих параметров. Его неполный payload больше не заменяет полный список в AppShell. Событие запускает повторное чтение с той же директорией; принимается только самый новый ответ. MainContentPanel также использует полный каталог для проверки удаления и восстанавливает read-only карточки project/OMP из него. Проверены одинаковые slug с приоритетом проекта и сохранение OMP. Серверные исходники не изменялись; контракт записан в `evidence/skill-event-contract.json`.
3. **Сохранение редактора при ошибке фонового чтения.** Сбой повторного GET не доказывает удаление workspace-навыка. Уже открытый редактор теперь сохраняет компонент, фокус и несохранённый текст. Проверка до исправления воспроизводит потерю ввода; после исправления проходит. Первоначальная ошибка по-прежнему получает отдельное состояние недоступности. Это не утверждение о сохранении черновика при каждом типе внешнего обновления.
4. **Сохранённые исправления размеров и пространств.** Живые и сохранённые Jotai-значения конечны, округлены и ограничены: inspector 280–1400 px, dock 88–480 px, defaults 320/104. Ранее исправлены stale callbacks, восстановление ширин, отмена незавершённого resize и запись старых фильтров в новое пространство. В продолжении реальные browser localStorage, второе окно, reload, удаление ключа, clear, запрет доступа и unsubscribe подтверждают эти свойства.

## Общее маршрутизирование: конкретное предложение для ведущего

Неизменённый парсер ещё переводит `knowledge/unknown-kind/one` в sessions и выбрасывает URIError для `%E0%A4%A`; старый resolveAutoSelection заменяет отсутствующую явную сессию другой. Read-only probe повторён на финальном продукте.

`lead-route-recovery-proposal-v4.patch` предлагает типизированное unavailable-состояние с raw route, безопасную ошибочную кодировку, восстановление unavailable и legacy /chat/ panel keys, сохранение явной удалённой сессии и проверку workspace. Проверка настоящих замыканий дополнительно обнаружила, что navigate отбрасывает unavailable до рендера, очередь теряет адрес/options, а повторное вычисление focused state теряет workspace-mismatch. V4 исправляет эти пути в предложении, сохраняя action navigation. После готовности очередь повторно вызывает navigate с полным адресом/options.

Проверены 38 behavioral checks, агрегация 67 parser/history tests (66 без изменений, 1 с предложенным новым ожиданием) и полный TypeScript — 40 успешных проверок верхнего уровня. Предложение не применялось к физическим shared source или старому тесту. SHA-256: `5b0b266239bd8e133d2e1d0b3dbad21fed322c08ae0c9685a96bd5bbb2984880`. Первый кандидат и версии v2/v3 сохранены вместе с отрицательными результатами; v3 проходил parser/type проверки, но провалил шесть проверок реальных callbacks. V4 повторно квалифицирован с финальными source hashes. Это готовый review artifact, а интеграция принадлежит ведущему по исходной инструкции «Shared route-parser belongs to lead: propose patch there, don't edit».

Отдельный `lead-layout-test-proposal.patch` предлагает заменить хрупкий source-text regex проверкой значения реального атома; не применён. Прежний sash fixture требует решения своего владельца, исходную константу и тест UI-001 не менял.
