# Программа сверки и завершения Rox — 2026-09-30

## Назначение и источник истины

Продолжить существующую программу Rox, Conation, RMA и Golden Gate по последним пользовательским требованиям. Этот документ — интеграционная надстройка над действующими issue и планами, а не второй независимый backlog. Полный частный экспорт и точные исходные критерии сохраняются локально; их публикация в этом публичном репозитории не предусмотрена.

Продуктовые требования проверяются в порядке: исходное поручение → последняя пользовательская корректировка → актуальный код/issue → наблюдаемое поведение. Сообщение агента «готово», merge, наличие обработчика или успешная компиляция не заменяют приёмку сценария.

## Объём и наблюдаемые результаты

1. Сверка: каждый исходный критерий имеет provenance, актуальную применимость, отдельное состояние реализации/проверки/доставки, владельца, зависимости и следующее действие. Неоднозначные ответы виджетов не создают новую авторизацию.
2. Аудит: каждый актуальный экран, модуль, действие и переход проверены в настоящем приложении. Покрытие включает загрузку, пустое состояние, ошибку, повтор, сохранение, повторное открытие и связанные сущности. Карта экранов из исходников — стартовый список, не предел покрытия.
3. UI: последняя компактная навигация, все необходимые экраны в верхней панели, отдельный Home, Inter, исходный прозрачный логотип, имя в onboarding, настройка провайдеров в Settings, согласованные темы и актуальные остаточные дефекты.
4. Runtime: реальный бюджет ограничивает исполнения; Focus управляет доставкой вопросов/уведомлений; автоматизация продолжает предусмотренную сессию и сохраняет webhook; cloud handlers загружаются runtime; Windows persistence выдерживает отказ и прерывание.
5. Голос/встречи/Mac mini: фактическая модель обычного voice input установлена отдельно от Meetings; настоящая русская edge-tts с остановкой и offline fallback; запись, ASR, структурированные результаты встречи, Tasks, сохранение и синхронный mini mode.
6. Проекты/граф/Quest: реальные материалы превращаются в сохраняемые спецификации и задачи, roadmap показывает этапы и результат, обычная сессия использует связанный контекст заметок с понятным пользователю происхождением; Quest отражает реальные действия.
7. Mail: постоянный локальный Stalwart и JMAP Inbox. Локальная приёмка и внешняя доставка — независимые критерии; loopback не закрывает внешнюю доставку.
8. Collaboration: настоящие идентичности, участники, роли, presence, общие данные, recipient Inbox, handoff/review, Slack backend и предусмотренные подключения. Локальная очередь не заменяет обмен между участниками.
9. Conation: весь подробный исходный checklist, включая авторизованные данные, каждый модуль, dashboard composition, documents/canvas, E2E, desktop, deep links и доставку. Issue #389 имеет собственные критерии media sessions и meeting bots.
10. RMA/Golden Gate: настоящий E3 product path для #385; #387 после подтверждённой зависимости; shell-grid/spatial/device сценарии #556/#557/#558; полные критерии #541/#578; итоговая матрица всей программы.

## Модель доказательств

Для каждого сценария сохраняются: requirement/task/issue, исходная и последняя корректировка, версия source и bundle, окружение, предварительные условия, действие, ожидаемое значение, наблюдаемое значение, результат, снимок/AX/API/store receipt, доставка и следующий шаг.

Состояния независимы:

| Измерение | Допустимые выводы |
| --- | --- |
| История | заявлено готовым / отложено / заменено |
| Код | реализовано / частично / дефект в проверенном пути / не установлено |
| Проверка | source inspection / реальный сценарий / пробел покрытия |
| Доставка | локальная ветка / commit / PR / merge / установленная проверенная версия |
| Зависимость | выполнена / внешняя блокировка с точным условием / требуется решение |

Отсутствие аккаунта, ключа или Windows-среды означает отсутствие соответствующей проверки. Открытый issue сам по себе не доказывает дефект. Несколько требований могут использовать одну реализацию, но приёмка каждого остаётся отдельной.

## Критерии сохранности и границы

- Не менять shell/workbench defaults или Map на основании неоднозначной записи U25. Исследование фактического поведения Map остаётся частью общего аудита.
- Не возвращать Arial Narrow, expanded sidebar и другие заменённые решения.
- Не включать предложения агента об импортёре JSON-тем Zed, Liquid Glass, system audio и Zoom/Meet в обязательную разработку без пользовательского требования. Запрошенные Flexoki Dark, Snazzy и Snazzy Blurred сохраняются как обязательные темы.
- Сохранять чужие изменения и действующих владельцев CTN/других worktree. Один владелец общей поверхности записи.
- QA-записи имеют явный префикс и известные ID; чужие записи не удаляются. Отдельный workspace не изолирует глобальные Mail/Meetings/Memory/preferences.
- Полный частный экспорт, credentials, cookie archives и внутренние agent missions не публикуются с этой документацией.
- Повторять затронутую приёмку после постоянных изменений. Windows доказательства получают на Windows; provider-live — на реальном предусмотренном провайдере.

## Условие завершения

Программа завершена только после закрытия каждого обязательного критерия в доставленной проверенной версии. Для внешне заблокированных критериев сохраняются причина, предпринятые попытки и точное условие продолжения; такой критерий не получает PASS и этап не получает статус «завершён».
