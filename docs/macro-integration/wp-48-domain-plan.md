# WP-48 implementation and verification handoff

## Dependency order and owners

1. Root integrates existing attribution collectors, exact multi-component bundle linkage and checker release gates. Genuine scoped human review remains independent.
2. Root reviews/applies backend-v3, which supersedes the rejected immutable backend-v1/v2 proposals. It includes canonical contracts, license migration/repository/registry/gateway, additive HTTP/WS composition and trusted outbound Resource guard. Existing identity scope and ordinary project replay are preserved.
3. Root applies native-v1 only against the recorded exact bases, including the test fixture adaptation after backend-v3. Existing authority routing, IPC and encrypted intent mechanism are extended; no user data or checkout configuration is seeded by these patches.
4. Worker verifies actual PG/HTTP/WS, canonical accounts, checker subprocess, encrypted subprocess recovery and ordinary Project offline regression in owned fixtures. Independent reviewer repeats the original corruption assertions on sealed v3.
5. Root runs normal service/Electron typecheck and builds against the integrated revision, then owns real native two-account/reload evidence. Any mismatch is corrected with a new exact patch; historical failed manifests remain intact.

## Required behavioral proof

- Real final archive/checker byte tampering fails before effect; no fabricated reviewer approval is accepted.
- Member/outsider, Actor/path/approval/workspace/schema forgery are denied, with no private title or server paths in denied output.
- Concurrent HTTP/WS command and listener/key/PG pool restart recover one original receipt and one atomic event with the same canonical entity.
- Stale revision and changed idempotency payload fail; session expiry during real checker I/O rolls back all effects.
- Every immutable label/binding/artifact/SBOM column is independently corrupted; GET and LIST fail over both transports.
- Invalid event digest, valid but wrong correlation, valid UUID for an absent Resource and coherent projected evidence/hash changes fail across receipt/read/event/inbox boundaries.
- Resource READ revocation is synchronized between domain completion and HTTP/WS outbound serialization; no private DTO is returned.
- SIGKILL after actual encrypted queue persistence, offline new process, service restart and explicit retry retain the original command/key/payload and produce one durable effect. Project conflict, forged Actor and unknown future format are rejected without replacing pending bytes.
- Existing nine Project offline tests run with their assertions unchanged.
- Deliberate isolated product source mutations must make the unchanged acceptance assertions fail. They are negative controls, never accepted source.
- New and added syntax contains no `any`, non-null assertion, broad type suppression or disabled test. All twelve installed locale files have the same new keys, ASCII ordered.

## Historical failures retained

- Backend-v1 removed the existing authenticated identity endpoint; root rejected that hunk. Backend-v2 restored it and added regression tests.
- Independent real v2 probes found LIST immutable proof, event digest/correlation, inbox Resource proof and coherent projection defects. Backend-v3 contains the common real proof and the matching strengthened cases.
- An early cold subprocess test hit 30 seconds while two full fixture typechecks were running. The failed log is retained; subsequent actual subprocess checks pass with bounded 120-second lifecycle timeout.
- A UUID negative fixture passed JSON text through Bun's inferred JSONB parameter, adding quotes to the stored value. It is corrected to `to_jsonb($1::text)` with raw text, so the format and independent-reference assertions test the intended corruption.

## Remaining external acceptance gates

- Root applied-revision readback, full integrated typecheck/build and actual native screenshots/keyboard/actions/two-account denial/reload.
- Real qualified review of complete scoped notices and exact artifacts. Existing baseline notices and synthetic fixture review-required results are not release clearance.
- Actual WP-04 durable DLQ/consumer policy, if normative WP-48 closure requires that generic primitive; existing retry counters alone do not claim it.

Proof logs and manifests are outside the checkout under `/tmp/rox-wp48-domain/`. Only root integrates patches. No worker source/build/UI/Git mutation occurs in the shared checkout.
