# Процесс лейнов (T15)

Рабочие правила для всех лейнов (`slice/*`), дополняющие план
[`2026-10-10-main-guardrails-and-ui-to-code.md`](./2026-10-10-main-guardrails-and-ui-to-code.md).
Файл самодостаточен: правила, порядок фиксации точек отката и журнал инцидентов — ниже.

## 1. Правила

1. **Кто слил красное в main — чинит первым делом.** Красный main (кроме явно внешнего, п. 5) —
   стоп новой работе: локализуй, почини или откати; новое начинается только после зелёного main.
   Цель — красный main не дольше 15 минут.
2. **Перед крупной волной — точка отката.** Ветка-срез и её SHA фиксируются в плане или описании
   PR **до** начала волны. Это известное доброе состояние, к которому можно вернуться.
3. **Самопроверка среза.** Перед слиянием срез прогоняет: (а) затронутые наборы тестов,
   (б) проверку типов, (в) для UI — визуальную проверку. Результат фиксируется в PR.
4. **Доказательства привязаны к ревизии.** Все артефакты (логи, скриншоты, замеры, вывод тестов)
   указывают SHA проверяемой ревизии; «примерно на этой ветке» не считается доказательством.
5. **Внешнее кодом не чинится.** Отказ внешнего сервиса (Vercel, провайдер и т. п.) фиксируется
   как внешний и эскалируется владельцу, а не «лечится» правкой кода.

## 2. Точка отката и откат

- **Фиксация:** `ветка-срез @ <SHA>` + дата — в плане/PR до волны. Для волны точкой отката служит
  коммит main непосредственно перед первым слиянием волны.
- **Сам срез тоже точка отката:** каждая ветка `slice/*` до слияния — кандидат на самостоятельный
  откат; слияние идёт только через PR (правила main: `deletion`, `non_fast_forward`, `pull_request`,
  `required_status_checks`/`freshness`).
- **Действие отката:** `git revert` диапазона слияний волны либо возврат main к зафиксированному SHA
  (force не разрешён — только revert/PR).

## 3. Самопроверка среза — чек-лист

| Проверка | Что приложить в PR |
|---|---|
| Затронутые наборы тестов | команда + результат (лог/счётчик) |
| Типы | команда + результат (`tsc`/аналог) |
| Визуал (только UI) | скриншот + SHA ревизии |
