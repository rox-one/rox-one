# T2 — трение практики «обновление перед слиянием» (замер 2026-10-13)

**Окно:** все слияния в main с момента активации свежести (2026-10-10T15:55:06Z, слияние носителя PR #1789) по 2026-10-13T09:45Z — 18 слияний.
**Метрика A (как в базовой линии):** `mergedAt` − committer-дата коммита-вершины ветки (`headRefOid`).
**Метрика B (собственное трение правила):** `mergedAt` − момент, когда проверка `freshness` стала зелёной.

| Метрика | A: после (n=18) | A: после, без носителя #1789 (n=17) | A: база из плана | A: база пересчёт (последние 60 до cut) | B: после (n=18) |
|---|---|---|---|---|---|
| медиана, мин | 10.0 | 8.65 | 0 | 0.55 | 0.33 |
| p90, мин | 25.1 | 22.7 | 12 | 2.9 | 2.08 |
| макс, мин | 37.9 | 30.9 | 1182 | 142.7 | 4.22 |
| застряло >15 мин | 7 | 6 | — | — | 0 |

**Причины задержек >15 мин (7 PR):** #1789 (37.9) — сам носитель, слияние через 6 с после включения правила (правилу не подчинялся); #1802 (30.9), #1805 (25.1), #1810 (22.7), #1787 (21.7), #1804 (20.6), #1799 (17.5) — **не устаревание**: у каждого ровно один прогон `freshness`, все `success`, ветка на момент слияния была свежей. Задержка = пауза между последним синк-коммитом и кликом слияния + ожидание необязательных (не красных для гейта) работ.
**Циклы обновления (наблюдаемое трение):** 45 коммитов «Merge …origin/main» на 18 PR = 2.5 на PR (макс 7 — #1811, 6 — #1805, 5 — #1804/#1809). Единственная обязательная проверка — `freshness` (strict); красные `lifecycle`, `durable-runtime`, `route-fixtures`, `fresh-native-smoke`, `browser-and-domain`, `Renderer bundle-size budget`, `UI token lint ratchet` слияние не блокируют.

**Вердикт: вяло (формально).** Порог «не хуже +20 % по медиане» при базовой медиане 0 мин даёт порог 0 мин — недостижим при любом ненулевом трении; фактически медиана 0 → 10 мин. При этом собственное трение правила (метрика B) ≈20 с, а рост метрики A даёт обязательный цикл «обновить ветку» (2.5 синка/PR) и латентность агентов, а не блокировка свежестью. Резерв плана (очередь слияния) по этим данным не требуется; при жёстком чтении порога — рассмотреть.

## Воспроизведение

```bash
export PATH=/opt/homebrew/bin:$PATH
cd /path/to/rox-one            # клон с полной историей + аутентифицированный gh
gh pr list --repo rox-one/rox-one --base main --state merged --limit 200 \
  --json number,mergedAt,headRefOid > /tmp/prs.json

python3 - <<'PY'
import json,subprocess,statistics
from datetime import datetime
def dt(s): return datetime.fromisoformat(s.replace('Z','+00:00'))
CUT=dt('2026-10-10T15:55:00Z')
d=[p for p in json.load(open('/tmp/prs.json')) if p['mergedAt'] and dt(p['mergedAt'])>=CUT]
v=[]
for p in d:
    cd=subprocess.run(['git','show','-s','--format=%cI',p['headRefOid']],
                      capture_output=True,text=True).stdout.strip()
    v.append((dt(p['mergedAt'])-dt(cd)).total_seconds()/60)
v.sort(); n=len(v)
print(f"n={n} median={statistics.median(v):.2f} p90={v[round(0.9*(n-1))]:.2f} "
      f"max={max(v):.2f} >15min={sum(x>15 for x in v)}")
PY
```

Список слияний перепроверен по истории: `git log origin/main --merges --first-parent --since=2026-10-10T15:55:00Z` → 18 строк.
Метрика B: `gh api repos/rox-one/rox-one/commits/<headRefOid>/check-runs` → `freshness.completed_at`.
Числа «база пересчёт» получены тем же скриптом на окне `mergedAt < CUT`, взяты последние 60 слияний (совпадает с методом метрики A; цифры плана — «медиана 0, p90 12, макс 1182» — этим методом не воспроизводятся и приведены как зафиксированные в плане).
