# Fail-closed контракт PreToolUse-хука и canary при старте сессии

## Установленные факты кода

- SDK Claude запускается с `permissionMode: 'bypassPermissions'` и
  `allowDangerouslySkipPermissions: true` (`claude-agent.ts:1266-1267`) —
  собственная система прав SDK отключена сознательно.
- ВЕСЬ контроль прав выполняется в одном внутреннем PreToolUse-колбэке
  (`claude-agent.ts:1278+`), вызывающем централизованный
  `runPreToolUseChecks()` (общий с pi-agent, `agent/core/pre-tool-use.ts`).
- Следствие: если колбэк не выстрелит хотя бы один раз (молчаливое падение
  регистрации, рассинхрон имени события в новой версии SDK, race teardown —
  см. комментарий :1188 о «hook_N stream closed»), тулы исполняются вообще
  без проверок. Это и есть fail-open, против которого направлен RX-TSK-0303.
- pi-agent.ts имеет собственные точки вызова того же пайплайна (:1233, :1306,
  :1352) — контракт должен закрывать оба бэкенда.

## Три варианта контракта

### Вариант A — отложенный bypass (предпочтительный)

Сессия стартует БЕЗ `bypassPermissions` (SDK сам спрашивает разрешение на
каждый тул). Первый выстрел нашего PreToolUse-колбэка доказывает живость
цепочки → агент программно переводит сессию в bypass (если SDK позволяет
смену режима на лету через control-request; проверить в используемой версии
`@anthropic-ai/claude-*`). До подтверждения — fail-closed: каждый тул
проходит явное подтверждение или отклоняется по таймауту.

- Риск: зависимость от API смены режима; если недоступен — деградация в B.
- Затраты: минимальные, точечные правки claude-agent.ts.

### Вариант B — эхо-сторож PostToolUse

Регистрируется парный PostToolUse-колбэк. Watchdog: если ≥N реальных тулов
исполнено, а ни одного события PreToolUse не зафиксировано — сессия
помечается `compromised`, все последующие tool-result блокируются и сессия
гасится с безопасной ошибкой.

- Не предотвращает первые N непроверенных вызовов (окно уязвимости),
  но гарантирует обнаружение и остановку.
- Работает при любом поведении SDK.

### Вариант C — canary-тул при старте сессии

После спавна сессии агент инициирует синтетический безобидный tool-call
(например, Read несуществующего служебного файла) и ждёт его отражения в
PreToolUse-журнале. Таймаут ~5 c: цепочка мертва → сессия не выдаётся
вызывающему коду (createSession фейлится), пользователь видит явную ошибку
вместо молчаливой дыры.

- Самый сильный контракт (проверка ДО первого реального действия), но
  требует управляемого синтетического вызова из агента.

## Рекомендация

A с деградацией в B: стартовать в подтверждающем режиме, после первого
фактического выстрела хука — переключить bypass; параллельно B-сторож как
страховка на весь жизненный цикл сессии. Canary C оставить как опцию
для headless-транспорта, где подтверждения некому отдавать.

## Критерии готовности реализации

1. Ни одна сессия не находится в bypass до первого задокументированного
   выстрела PreToolUse (лог + внутренний флаг).
2. Разрыв цепочки детектируется и гасит сессию (B) — юнит-тест на
   симулированном отсутствии событий.
3. Поведение pi-бэкенда покрыто тем же контрактом.
4. Оба существующих тестовых файла pre-tool-use остаются зелёными.
