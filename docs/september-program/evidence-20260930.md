## Значение ограниченных доказательств

Native credential хранится в CredentialManager по workspace и приватно разрешается main на каждое подключение. Повреждённое или недоступное хранилище, revoked credential, чужой principal/root и stale window вызывают отказ; legacy fallback применяется только при отсутствии enrollment. Renderer не выбирает authenticated issuer/subject и не получает публичный credential setter/getter. Operator enrollment/storage API реализован; first-run enrollment UX остаётся открытым.

Startup summary возвращает только `kind`, `slug`, `providerType`, `isDefault` и помечен `configuration-only`. Он не раскрывает host accounts, не читает/обновляет credential или OAuth и не меняет host configuration. Production main proof проверяется перед обработчиком, после awaited success/error и перед доставкой native event. Workspace startup отдаёт только собственную разрешённую запись и связанные window metadata, исключая чужой roster и remote credentials.

Privacy fixes проверяют точную custody принадлежащих import ключей и rollback ciphertext, восстановление и resumable deletion, уменьшение consent scope и revoke прежнего профиля. Используются реальные local files/ledger и fixture protected-key/Electron-cookie ports. Live browser/Keychain чтение, OS crash windows и полный Privacy UI/export/delete не приняты.

Managed OMP 17.2.10 через реальные metadata RPC возвращает пять точных public IDs: `rox/explore`, `rox/fast`, `rox/max`, `rox/standard`, `rox/vision`; выбран `rox/standard`. Это provisioning объявленного каталога с явно non-authenticating fixture и без prompt/provider request. Actual OmpAgent lifecycle использует реальный CLI subprocess и encrypted selected-connection fixture credential; это не подтверждение authenticated gateway discovery, billing, реального R1 inference или доступности провайдера.

Предыдущее объяснение fixture stalls через late-disconnect retention timer **отозвано как неподтверждённое**. Изолированный child с реальным WS запросом, `server.close()` и наблюдаемым disconnect выходит естественно, без `process.exit`, `unref`, очистки timers или server internals. Shutdown defect не воспроизведён; production shutdown fix не выполнялся.
