## A. Принципы

1. **Консистентность с DESIGN.md** (`DESIGN.md`). RU-first; графит + один акцент Rox; 4/8px сетка;
   радиусы 6–8px (контролы) и 10–12px (плавающие поверхности); тонкая граница + сдержанная тень; RU-копирайт
   по глоссарию пака (`00-BRIEF.md` §7, README). Термины UI: `репозиторий`, `репо-воркспейс`, `снапшот`,
   `артефакт`, `вопросы`, `тур`, `плейбук`, `кодбук`, `источник`. Без непереведённого `memory`/`runtime`.
2. **Токены, а не литералы.** Цвет/типографика/отступы/радиусы/моушн — из `packages/ui/src/styles/tokens/*`
   (`tokens/index.css` собирает группы). Локальные hex/тени запрещены (DESIGN.md «Implementation constraints»).
3. **Моушн.** DESIGN.md задаёт «160–220 ms ease-out» для коллапса рейлов; фактические токены —
   `packages/ui/src/styles/tokens/motion.css`: `--motion-instant:0ms`, `--motion-fast:120ms`,
   `--motion-base:180ms`, `--motion-slow:240ms`, алиас `--motion-normal = --motion-base`. Экраны используют
   `--motion-fast` для hover/фокуса, `--motion-base` для панелей/дискложеров, `--motion-slow` для крупных
   переходов поверхностей.
4. **Reduced-motion.** `motion.css` гасит `--motion-fast/base/slow` до `0ms` и при
   `@media (prefers-reduced-motion: reduce)`; дополнительно Tailwind-утилиты `motion-reduce:*` (пример
   применения — `TourPopover.tsx`: `motion-reduce:transition-none motion-reduce:animate-none`). Анимация
   тура (D10) при reduced-motion заменяется статичным градиентом без пульса (детали §B.11).
5. **Одна поверхность — одна мысль.** Один экран решает одну задачу и не смешивает по смыслу разные наборы
   контролов (DESIGN.md «One surface, one mental model»): чтение wiki ≠ review wiki; граф кода ≠ C4;
   вопросы ≠ чат-сессия (чат внизу блока, D11).
6. **Пустое состояние = одно конкретное действие.** Пустой экран всегда даёт ровно одно первичное действие
   на русском (DESIGN.md «Empty: give one concrete next action»). Пример: Home без репо → «Вставить ссылку
   на репозиторий».
7. **Прогрессивное раскрытие.** Дополнительные рейлы (инспектор доказательств, дерево) сворачиваются без
   потери контекста (DESIGN.md «Reveal complexity progressively»); на узком окне превращаются в sheets (§B.0).
8. **Каскад и честность состояний (D5, D8).** Структурные артефакты показываются сразу, LLM-слой — фоном с
   прогрессом; экран обязан различать «не проверено» и «пусто/ноль» (RC §3: `failed scanner means «не
   проверено», not zero dependencies`).
9. **Источник правды — состояние, не оформление.** Любой артефакт маркируется provenance (снапшот, инструмент,
   версия), генерированный контент визуально отделён от проверяемого кода (RC §4–5). Бейджи статусов —
   в §B.4/§B.8.

## B. Экранная карта

### B.0 Шаблон описания и общие правила

Каждый экран описан семью блоками: **Цель** → **Зоны компоновки** → **Состояния** → **Действия** →
**Клавиатура** → **Адаптив <900px** → **Токены/моушн**.

Общие правила (не повторяются в каждом экране):

- **Каркас.** Экраны рендерятся в общей оболочке: destination — `APP_NAV_DESTINATIONS`
  (`apps/electron/src/renderer/components/app-shell/nav-destinations.ts`), потребители — `AppShell.tsx`
  (`links[]`) и `platform/ActivityRail.tsx` (rail groups), рендер — `MainContentPanel.tsx`.
  Заголовок — существующий `PanelHeader` (пример использования: `pages/settings/LearningSettingsPage.tsx`).
- **Состояния (полный набор).** Каждый экран обязан иметь пять базовых состояний: `empty`, `loading`,
  `error`, `partial`, `offline`. При наличии — дополнительные из §C. Списки данных — skeleton, не «чёрный
  прямоугольник» (DESIGN.md «Loading»). Ошибка говорит, что осталось локально, и даёт восстановимое действие
  (DESIGN.md «Error»). `offline`: локальные артефакты доступны, облачные/сетевые операции помечены вторично
  (DESIGN.md «Offline/slow network»; RC §3 offline-политика; у нас — пер-repo consent D6).
- **Фокус.** Видимый focus-ring: существующие токены ring (`focus-visible:ring-1 focus-visible:ring-ring`,
  напр. `MarkdownHtmlBlock.tsx`). Печать «порядок фокуса = порядок чтения», начало — с заголовка
  (RC CI-UI-01 `Focus begins at heading`).
- **Клавиатура (общая).** Enter — подтвердить/открыть, Escape — закрыть транзиентную поверхность (не
  документ, DESIGN.md), стрелки — навигация внутри сфокусированного списка (не глобальные шорткаты,
  RC CI-UI-02). Шорткаты тура — §B.11/§D.
- **Адаптив <900px.** Левое дерево и правый инспектор превращаются в sheets (RC-01 layout; существующий
  sheet-паттерн — `apps/electron/src/renderer/components/session-workbench/SessionFanOutSheet.tsx`).
  Порог 900px — из RC-01..12; существующий DESIGN.md-брейкпоинт «narrow split panels» совместим.
- **Токены/моушн (общая база).** Hover-заливка строк `foreground/5`, переход `--motion-fast`; раскрытие
  панелей/дискложеров `--motion-base`; смена крупных поверхностей `--motion-slow`; всё с `motion-reduce:*`.
- **i18n.** Любая новая строка — RU-источник + 11 локалей (`packages/shared/src/i18n/locales/*.json`;
  ключи ASCII-sorted; гейты `lint:i18n:parity|sorted|coverage`).

Открытые общие вопросы: точный job-движок для длинных пайплайнов — `TODO(open)` O3 (влияет на отображение
прогресса/отмены во всех экранах анализа); канонический codegraph-провайдер — `TODO(open)` O1 (влияет на
§B.7); хранилище клонов — `TODO(open)` O4 (влияет на §B.1/§B.2).

### B.1 С-01 — «Разработчикам» — Home

**Цель.** Точка входа Developer Space (D2): каталог подключённых репозиториев со статусами и единственным
действием «подключить репозиторий».

**Зоны компоновки.**
- Верхнеуровневый пункт «Разработчикам» — **новое** значение в `APP_NAV_DESTINATIONS`
  (`nav-destinations.ts`, правило «add once»); `route`/active-predicate — **новое** (расширение реестра
  навигации). Видимость пункта управляется онбординг-ролью/флагом (D1) — конкретный флаг описан в
  `02-SPEC-foundations.md`, здесь не изобретается.
- Экран Home — **новое**: `apps/electron/src/renderer/pages/dev-space/DevSpaceHomePage.tsx`; регистрация
  пункта/флага — аддитивные правки `AppShell.tsx` (`links[]`) и `platform/ActivityRail.tsx` (rail groups);
  поведение существующих пунктов не меняется.
- Заголовок (`PanelHeader`) + кнопка «Подключить репозиторий» (primary).
- Сетка карточек репозиториев (**новое**): имя/источник, ветка, бейдж свежести (актуально/устарело,
  §B.3), сводка шести артефактов (готово / генерируется / нет), число блоков вопросов.
- Вторичная зона: «Недавние прогоны» (последние джобы анализа) — те же строки, что журнал §B.3.

**Состояния.**
- `empty` (нет репо): иллюстрация-заглушка + одно действие «Вставить ссылку на репозиторий» (открывает
  §B.2). Если роль «не разработчик» — вместо этого карточка «Включить экран разработчика?» с одним действием
  (D1, мягкое напоминание; молчаливого автовключения нет).
- `loading`: skeleton-сетка карточек.
- `error` (каталог не прочитан): сообщение + «Повторить».
- `partial`: часть репо без карточки-сводки (артефакты ещё не публиковались) — карточка со статусом «не
  анализирован» и действием «Проанализировать».
- `offline`: карточки локальных репо доступны, кнопка «Подключить репозиторий» предупреждает о недоступности
  клонирования по сети; GitHub-логин — недоступен (вторичный бейдж).
- Дополнительно: `permission-denied` (репо отозван) — карточка с бейджем и действием «Обновить доступ».

**Действия.** Подключить репозиторий; открыть репо (→ §B.3); «Проверить свежесть/обновить» (паттерн
freshness code-intelligence, D3); удалить из каталога (обратимо, confirm); открыть прогон.

**Клавиатура.** Tab по карточкам; Enter — открыть репо; контекстное меню карточки — Shift+F10/Menu; `/`
фокусирует поиск по каталогу (**новое** локальное поле, не глобальный шорткат). Начало фокуса — заголовок.

**Адаптив <900px.** Сетка карточек → одна колонка; «Недавние прогоны» → sheet, открываемый кнопкой в шапке.

**Токены/моушн.** Карточки — радиус `--radius-card` (как `MarkdownHtmlBlock.tsx`), тень hover `--motion-fast`;
появление новых карточек после подключения — `--motion-base` fade/slide с `motion-reduce`.

### B.2 С-02 — Подключение репозитория

**Цель.** Принять источник (git-URL или локальная папка), выполнить GitHub-подключение при необходимости,
показать шаг consent «что уходит», запустить клонирование/ингест с прогрессом (D3, D6).

**Зоны компоновки.**
- Экран-мастер — **новое**: `apps/electron/src/renderer/pages/dev-space/DevSpaceRepoPage.tsx`.
- Один экран-мастер с шагами: **1) Источник** → **2) Доступ** (GitHub, если приватный; иначе пропуск) →
  **3) Consent «что уходит»** → **4) Прогресс ингеста**.
- Шаг 1 (**новое**): поле ввода URL + переключатель «Ссылка / Локальная папка»; для папки — существующий
  выбор директории (`composer.directory`-паттерн; в тур-контрактах есть target `composer.directory`,
  `contracts/index.ts`) — переиспользовать файловый селектор, не изобретать.
- Шаг 2 (GitHub device-login): переиспользовать существующий контур
  `workgraph:startGithubDeviceLogin|pollGithubDeviceLogin|cancelGithubDeviceLogin`
  (`server-core/src/workgraph/github-oauth-import.ts`). **Токен в рендер не выходит**; UI показывает код
  устройства и статус ожидания. Clone-API пока нет — новый RPC-контур
  `packages/server-core/src/handlers/rpc/dev-space.ts` (**новое**), спецификация — `02-SPEC-foundations.md`;
  UI лишь отображает его состояния.
- Шаг 3 Consent «что уходит» (**новое**, аналог гейта PREVIEW/BIND, D6): список категорий эгресса
  (модельные коннекты / сеть CVE-OSV / обновления инструментов) с per-category тумблером; дефолтные
  исключения `.env*`, `**/*.pem`, `**/*.key`, `**/.codegraph/**` показаны как **неотключаемые**; кнопка
  «Разрешить и начать» неактивна без осознанного подтверждения. Молчаливого эгресса нет.
- Шаг 4 Прогресс (**новое**): этапы клонирование → scope/exclusions → структурный индекс → (фон) LLM-слой;
  полоса прогресса + текстовый статус этапа; `aria-live` (§D).

**Состояния.**
- `empty` (пустое поле): подсказка формата ссылки, кнопка неактивна.
- `loading`: валидация URL/пути, затем прогресс-этапы.
- `error`: невалидный URL/путь (напр. выход за root, symlink-escape — RC §5); «auth missing» для приватного
  репо; «clone failed»; «root rejected». У каждого — конкретное восстановимое действие.
- `partial`: клонирование завершено, структурный индекс ещё идёт — можно работать, LLM-слой помечен «фон».
- `offline`: клонирование по сети невозможно — предложить локальную папку (единственное доступное действие).
- Дополнительно: `consent-declined` — ингест не стартует, экран возвращается к шагу 3.

**Действия.** Вставить ссылку; выбрать локальную папку; войти в GitHub; переключить категорию consent;
начать ингест; отменить; вернуться к предыдущему шагу.

**Клавиатура.** Enter — следующий шаг, если шаг валиден; Escape — назад по шагам (не закрывает мастер при
заполненных данных без подтверждения); фокус-ловушка внутри активного шага — стандартный dialog-паттерн
Radix (как в существующих диалогах). Начало фокуса — заголовок шага.

**Адаптив <900px.** Мастер остаётся одноколоночным (уже узкий); список категорий consent и легенда исключений
→ аккордеон/sheet.

**Токены/моушн.** Переход между шагами — `--motion-base` (slide/fade) с `motion-reduce`; прогресс-полоса —
без анимированных полос при reduced-motion (статичная заливка).

### B.3 С-03 — Репо-воркспейс → Обзор

**Цель.** Сводка по репозиторию: свежесть снапшота, обновить/перегенерировать, шесть разделов-артефактов,
журнал прогонов (RC-02 + RC-12 в объёме обзора).

**Зоны компоновки.**
- Шапка: имя репо, ветка, неизменяемый SHA снапшота/`sourceRevision`, бейдж свежести (актуально/устарело,
  паттерн freshness `packages/shared/src/code-intelligence/refs.ts`), «дифф рабочего дерева» при `dirty`
  (RC §5), кнопки «Проверить свежесть», «Обновить», «Перегенерировать» (**новое**, D7 — по кнопке при новом
  снапшоте; авто-регенерации нет).
- Вторичная навигация (tabs): **Обзор, Wiki, Схемы, Граф кода, C4/Groma, Понимание, Вопросы, Прогоны** —
  **новое** расширение набора RouteKey (`contracts/index.ts` `RouteKey`; `apps/electron/src/shared/routes.ts`
  — добавить стабильные сериализуемые роуты; имена роутов новое). Существующий визуальный паттерн вкладок —
  `SurfaceTabs` (DESIGN.md «Existing components to reuse»).
- Центр: сетка из 6 карточек-разделов (по одному артефакту на инструмент, D4): статус (готово/генерируется/
  нет/устарел/ошибка), инструмент+версия, ссылка на страницу в Notes/Pages (публикация D7), «Открыть».
- Низ/правая зона: журнал прогонов (таблица: этап, статус, время, длительность, стоимость/токены «если
  известно» — RC-12), кнопки отмена/повтор/резюм.
- Правый инспектор (сворачиваемый): provenance, политика эгресса репо, ссылки на receipts.

**Состояния.**
- `empty` (репо без анализа): скелет сразу + действие «Запустить анализ» (каскад D5).
- `loading`: skeleton карточек и журнала; первыми появляются структурные артефакты, LLM-слой — по мере
  готовности (RC «progressive»).
- `error`: различать «не проверено» (failed scanner) и «пусто/нет данных» (RC §3); «устарело» ≠ «ошибка».
- `partial`: часть разделов готова; у остальных — статус «генерируется» с прогрессом; интерфейс рабочий.
- `offline`: структурные артефакты (codegraph/groma/graphify/archify) локально доступны; CVE-проверка (OSV)
  и модельные контуры помечены недоступными (D6).
- Дополнительно: `stale` (бейдж «устарело» при новом снапшоте), `dirty` (рабочее дерево изменено;
  ссылки на источник ведут на локальный диф, не на remote-commit — RC §5).

**Действия.** Обновить/проверить свежесть; перегенерировать (по команде, `TODO(open)` O8 — политика при
«грязном» дереве, дефолт «по явной команде»); открыть раздел; отменить/повторить/резюмировать прогон;
открыть артефакт в Notes/Pages.

**Клавиатура.** Tab по tabs (ARIA roving, как существующие `SurfaceTabs`), стрелки между вкладками;
Enter открывает карточку; Cmd/Ctrl+R запрещён для «обновить репо» (глобальный reload остаётся) — обновление
репо на кнопке/shortcut внутри поверхности (**новое**, точная привязка — решение дизайна, RC CI-UI-01).

**Адаптив <900px.** Инспектор и журнал → sheets; карточки разделов — одна колонка; tabs — горизонтальный
скролл со sticky-шапкой.

**Токены/моушн.** Смена вкладок `--motion-fast`; появление прогресса — аккуратное обновление полос без
layout-shift; `stale`-бейдж — цвет + текст (не только цвет, RC §4); анимации прогресса глушатся при
reduced-motion.

### B.4 С-04 — Wiki reader (RC-03)

**Цель.** Чтение сгенерированной repo-wiki (openwiki, D4/D5): страница с оглавлением, кросс-ссылками,
Mermaid-диаграммами и ссылками на источник.

**Зоны компоновки.** Трёхзонная, как RC-03:
- Лево: дерево страниц/разделов + поиск.
- Центр: рендер Markdown-страницы. Существующий markdown-пайплайн и рендер (Notes/Pages: block-tree
  `packages/core/src/docs/*`, `content:*` RPC `server-core/src/docs/markdown-commit.ts`); Mermaid —
  существующий path отображения кода/диаграмм. **Расширение**, не новый рендерер.
- Центр-верх: бейдж «Сгенерировано: провайдер/инструмент + версия + время + SHA снапшота» (RC-03/§4) —
  визуально отделять сгенерированную прозу от наблюдений по коду.
- Право: инспектор claims/sources — список утверждений со статусом (Source-verified / Inferred / Stale /
  Disputed / Unverified, RC §4) и ссылками на точный диапазон файла; клик открывает drawer доказательства.

**Состояния.**
- `empty`: «Wiki не сгенерирована» + одно действие «Сгенерировать» (→ §B.5 plan/review).
- `loading`: skeleton страницы.
- `error`: страница не найдена / повреждён артефакт — восстановимое «Перегенерировать раздел».

- Дополнительно: `stale` (страница устарела при новом снапшоте), `retracted-claim`, `read-only`,

цитате (→ viewer доказательств); инспектировать claim; запросить обновление раздела.

**Клавиатура.** ToC/заголовки — фокусируемы (RC-03 `Headings and ToC focusable`); Enter на цитате открывает
диапазон источника; стрелки — дерево страниц.

**Адаптив <900px.** Дерево и инспектор → sheets; центр остаётся страницей.

**Токены/моушн.** Drawer доказательства — `--motion-fast`; Mermaid-диаграммы без анимации layout при
reduced-motion (RC §4 «reduced-motion removes graph fly/pan animations» — применимо к диаграммам).

## D. Доступность

1. **Фокус.**
   - Видимый focus-ring на всех интерактивных элементах (токены ring; пример `focus-visible:ring-1
     focus-visible:ring-ring` в `MarkdownHtmlBlock.tsx`).
   - Порядок фокуса = порядок чтения; начало фокуса экрана — заголовок (`PanelHeader`).
   - Фокус-ловушки только в модальных поверхностях (Radix dialog); транзиентные поповеры (тур) —
     non-modal, без кражи фокуса (`SpotlightOverlay.tsx`: `Popover.Root modal={false}`; возврат фокуса
     только если он остался внутри поповера).
   - Escape закрывает транзиентные поверхности, но не документ (DESIGN.md). При handoff в модальные
     слои (ModalContext/DismissibleLayerContext, `SpotlightOverlay.tsx`) — фокус не восстанавливается
     принудительно.
2. **aria-live для прогресса.**
   - Прогресс анализа (С-02, С-03, С-13, С-14, С-15), reindex источников и синтез сегментов объявляются
     через `aria-live="polite"` (промежуточные статусы) и, при завершении/ошибке, `role="status"`/
     `role="alert"` — конкретный выбор на уровне компонента при реализации.
   - Прогресс «шаг N/M» тура (§B.11) — тоже live-регион (не чаще осмысленных изменений, чтобы не спамить
     скринридер).
   - `aria-valuenow/valuemin/valuemax` для determinate-полос; indeterminate — без ложных значений.
3. **Keyboard-шорткаты тура.** Escape — пауза/выход; Enter/→ — дальше; ← — назад; Space — пауза. Enter не
   прокидывается в целевые контролы (`TourPopover.tsx`). «Перейти к элементу» — доступно с клавиатуры
   (`focusTarget`). Наличие keyboard-управления pan/zoom (С-06) и outline-обхода графа (С-07) — обязательны
   (RC-06/CI-UI-04 «no hover-only controls»).
4. **Контраст.**
   - WCAG 2.1 AA для контраста и клавиатуры (DESIGN.md «Accessibility»); избегать серого текста на тёмном.
   - Статусы и рёбра графов не передаются одним цветом: бейджи — текст+иконка; inferred — пунктир + подпись;
     stale — затемнение + бейдж (RC §4 «color supplemented by labels»).
   - Виньетка тура (opacity 0.10–0.18) не должна снижать контраст подсвеченной цели ниже AA; при
     необходимости уменьшать непрозрачность или поднимать контраст рамки цели.
5. **Reduced-motion.** Все анимации (виньетка/дыхание, pan/zoom графа, disclosure, прогресс) гасятся при
   `prefers-reduced-motion:reduce` (токены `motion.css` → 0ms; `motion-reduce:*` утилиты; D10 — статичный
   градиент без пульса).
6. **Скринридер-семантика.** Заголовки образуют навигируемый outline; списки/таблицы — семантические
   (`role="grid"` для таблицы прогонов при необходимости); ARIA-expanded на деревьях (RC §4, пример
   требуемого поведения `chevron+aria-expanded`); диаграммы — с текстовым альтернативным описанием/списком
   (outline С-07).
