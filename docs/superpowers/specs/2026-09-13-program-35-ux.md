## Security hypotheses (need confirmation)

1. Security settings = local credential vault + Infisical-for-Rox + remote TLS + permission modes. Not a new IdP.
2. “Account & security” must not ask for a random email/token as if that were a working login.
3. Browser *profile discovery* at install without a consent prompt is a product call. Importing cookies/passwords still needs OS keychain / explicit persist.
4. Question: is Security a settings page for vault + TLS + permissions, or a full account-auth product?

## P35-02 Sessions + chat import

### PRD

Scan cap is too low (~200 / 80 per kind). Target scan budget is 100_000 entries. Persist is still explicit and batched (not 100k in one RPC). UI: keyword search, filter by kind/source, Select all / Clear. Additional kinds (ChatGPT, DeepSeek, Gemini, Qwen, Amp, Cursor, OpenClaw, OMP, Pi, Kiro, Kimi, GLM, Z) are a later converter slice — this PR only raises caps and list UX for existing kinds (`grok`, `claude`, `codex`, `opencode`, `hermes`).

### SPEC

- `MAX_SCAN_ENTRIES = 100_000`, `MAX_SCAN_PER_KIND = 20_000`.
- `MAX_FOREIGN_PERSIST = 5_000` per persist call (raise from 50). Streaming 100k persist is a follow-up.
- `filterForeignIndexEntries({ query, kind })` is pure and unit-tested.
- Import settings page: search input, kind select, select-all, selected count.

### PLAN

1. Raise caps.
2. Filter helper + tests.
3. Import page controls + i18n in all 12 locales.
